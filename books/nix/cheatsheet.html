The One-Page Helper Sheet

Real name: "Cheatsheet"
The thirty-second version

You write a description. Nix reads it (evaluation), writes a build plan (instantiation), then runs the plan in a closed room (realisation). The result lands in /nix/store at a path made from everything that went in. Same plan in, same path out. Nothing is changed in place; new things are added beside old things.

Writing it down: the small rules

ThingLooks likeWatch out
String"hi ${name}"${ } puts another value inside. Two single quotes make a many-line string.
Path./builder.shIt needs a slash. Without one, builder.sh is a name. Putting a path inside a string copies it into the store.
List[ "a" "b" ]Spaces, not commas. ++ joins lists.
Set{ port = 4000; }Every line ends with ;, even the last one.
Join setsa // bRight side wins. It only goes one level deep; inner sets are replaced, not mixed.
Local nameslet x = 1; in x + 1Names live only inside the part after in.
Choiceif c then a else bAn answer, not a command. The else is required.
Missing partset.x or 0Without or, a missing name is an error.
Self-referencerec { a = 1; b = a + 1; }rec is fine. A value that needs itself is the trouble.
Copy a name{ inherit x; }Same as { x = x; }.

Functions: one thing in, one thing out

ThingLooks likeWatch out
Functionx: x + 1Call it with a space: f 3. Not f(3).
Many inputsa: b: a + bEach function takes one input. add 1 alone gives back a new function.
Set as input{ name, port ? 4000, ... }: …? is a default. ... allows extra names; without it, extras are an error.
Whole setargs@{ a ? 1 }: …Defaults the caller skipped are not in args.
Other filesimport ./f.nix { … }import gives back the file's one value. If that is a function, the set after it is the input.
Each itemmap (n: …) listFunctions are plain values; pass them around.
Typical header{ pkgs, ... }: …callPackage fills each named input from the package set.
Scope—A function sees the names where it was written, not where it is called.

Shapes you will see again and again

{ pkgs ? import <nixpkgs> {} }:
pkgs.stdenv.mkDerivation {
  pname = "hello-c";  version = "0.1";
  src = ./src;
  patches = [ ./fix.patch ];
  nativeBuildInputs = [ pkgs.pkg-config ];   # tools that RUN while building
  buildInputs       = [ pkgs.zlib ];         # libraries that get linked or used
  makeFlags = [ "PREFIX=$(out)" ];           # never write outside $out
  meta = { description = "…"; mainProgram = "hello"; };
}
pkgs.mkShell {
  packages = [ pkgs.elixir pkgs.rustc pkgs.cargo ];
  inputsFrom = [ app ];            # take what building app needs
  MY_FLAG = "1";                   # becomes an environment variable
  shellHook = ''echo ready'';      # bash that runs on entry
}
{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  outputs = { self, nixpkgs }: let
    system = "x86_64-linux";
    pkgs = nixpkgs.legacyPackages.${system};
  in {
    packages.${system}.default = pkgs.hello;
    devShells.${system}.default = pkgs.mkShell { packages = [ pkgs.jq ]; };
    checks.${system}.default = self.packages.${system}.default;
  };
}
final: prev: {
  hello-c = prev.hello-c.overrideAttrs (old: {
    patches = (old.patches or []) ++ [ ./fix.patch ];
  });
}
{ lib, config, ... }:
let cfg = config.bakery; in {
  options.bakery = {
    enable = lib.mkEnableOption "the bakery";
    loaves = lib.mkOption { type = lib.types.int; default = 2; };
  };
  config = lib.mkIf cfg.enable { /* only when switched on */ };
}

Changing a thing someone else made

ToolWhat it changes
pkg.override { … }The inputs passed to the package function (dependencies, flags).
pkg.overrideAttrs (old: { … })The attributes of the build itself: patches, version, src, hooks.
Overlay final: prev: { … }The whole set. prev = before this overlay; final = finished set. Use prev.x to build on x; final.x inside x loops forever.
Local let + overrideOnly your own code. Enough when nothing else in the set must see the change.

Changing version without changing src gives a package that says "new" and builds old. Change both.

Options: say it once, set it many times

PieceJob
options.x = mkOption { type; default; }Declares what may be set. One file does this.
config.x = …Sets a value. Many files may.
listOf strLists from all files are joined.
int / str set twiceError, unless priorities differ.
Priority number (lowest wins)mkForce 50 · plain 100 · mkDefault 1000 · option default 1500
mkIf c vAdds v only when c is true.
mkMerge [ … ]Several definitions in one place. Two plain strings still clash.
imports = [ ./a.nix ]Pull in more modules. Their order does not decide who wins.

Words, in plain words

Derivation
A written-down build: the builder, its inputs, its settings. A description, not a result. Its file ends in .drv.
Output
What a build leaves behind. Most builds have one, called out, and the builder must put it at $out.
Store path
/nix/store/<32-letter hash>-name. The hash comes from the inputs, so different inputs never share a path.
Closure
A path plus everything it needs to run, and what those need, all the way down. Found by scanning for the hashes of other store paths.
Profile
A link to a fixed set of installed things. Every change makes a new, numbered generation.
Generation
One saved version of a profile (or a whole NixOS system). Old ones stay until you delete them, which is how rollback works.
GC root
Something that keeps a store path alive: profiles, generations, and the result link from nix build.
Overlay
A function final: prev: { … } that changes a package set. Everything depending on a changed package gets a new path.
Module
A piece that declares options and/or sets values; many pieces merge into one config. Modules configure; they do not build by themselves.
Flake
A folder with flake.nix (inputs, outputs) and flake.lock (exact input revisions). A fixed shape on top of the same language, not a new tool. In a git folder it only sees files git tracks.
Fixed-output derivation
A build that states its result's hash up front. Only kind allowed to use the network. This is how fetchers work.
Substituter
A binary cache to download from instead of building. cache.nixos.org is the default; its signatures must be trusted.

When it breaks: first, which room?

Ask one question first: did a "building" line show up? No → the trouble is before any build. Yes → the builder ran and failed. Do not change things at random until you know the room.

StageSignFirst move
1 · Syntaxsyntax error, unexpected … with line and caretLook at the line just before the caret: missing ;, unclosed [ or {.
2 · Evaluationattribute 'x' missing, undefined variable, infinite recursion encountered, called without required argumentRead the last error: line for the cause; the frames above are the route. Add --show-trace.
3 · Fetchingunable to download, or hash mismatch in fixed-output derivationNetwork or wrong hash. Check the source is the one you meant, then copy the got: hash.
4 · Buildingbuilder failed with exit code NThe real cause is the tool error just above it. nix log or -K to look around.
5 · ActivationFails during switch / home-manager switchExisting file in the way, or a service that did not start. Use test or boot first.

Checklists

Evaluation errors
  1. Typo? nme for name — Nix often suggests "Did you mean".
  2. n-1 is one name. Write n - 1.
  3. Adding a string and a number: use toString.
  4. Function got a set with extra names and no ..., or is missing one with no default.
  5. Infinite recursion: find the value that needs itself. Inside an overlay, did you write final.x where prev.x was needed?
  6. Error hidden by laziness? Force it: --strict, :p in the REPL, builtins.deepSeq (never leave it in real code).
  7. Narrow it: builtins.trace, builtins.tryEval (catches throw and assert, not abort), or load the file in nix repl and pick attributes one by one.
Build errors
  1. command not found / exit code 127: a tool was not declared. The sandbox is doing its job.
  2. pkg-config: command not found: put it in nativeBuildInputs. zlib.h: No such file: put the library in buildInputs. Fix one error at a time.
  3. Files written to /usr/local: set makeFlags = [ "PREFIX=$(out)" ].
  4. Hunk FAILED: a patch no longer fits; it broke in the patch phase, not the compiler.
  5. Raw builder said "ok" but the output is wrong: the script never checked its commands.
  6. Builder failed to produce output path: nothing was written to $out.
  7. Rust: no matching package named … offline — Cargo.lock is out of date or not in src. Stale cargoHash? Try cargoLock.lockFile.
  8. Elixir: fetchMixDeps hash keeps changing — not fetched the same way twice; use mix2nix.
Hash and fetch errors
  1. Set hash = lib.fakeHash; (or ""), build once, copy the got: value.
  2. New version but old hash → mismatch. Update both.
  3. Flake or git folder: is not tracked by Git means run git add. Also git add new files before CI sees them.
Flake and cache surprises
  1. Another machine gets Required system: outputs written for one system only, or no builder for that system.
  2. does not provide attribute: look at where it searched; run nix flake show.
  3. flake.lock not committed: each person gets a different revision.
  4. ignoring substitute … not signed by any of the keys: add the cache's public key. Overriding trusted-public-keys on the command line replaces the default, so keep the cache.nixos.org key.
  5. CI is green but tests never ran: it built the package only. Run nix flake check.
  6. Different package than expected: <nixpkgs> and nixpkgs# may be different revisions. Ask meta.position where it is defined.
Module and system surprises
  1. option … does not exist: a typo. Setting an undeclared option is an error, not a no-op.
  2. conflicting definition values: two plain values. Make the shared one mkDefault.
  3. is not of type …: wrong kind of value; the message names the file.
  4. Home Manager stops over an existing file: move it, or switch with -b.
  5. Edited a managed file by hand: it is a read-only link into the store; change the source and switch again.
  6. Rolled back, but the data is still new: rollback restores programs and settings, not what is under /var.

Things that bite everyone

Keep these in your head

The store is readable by every user. A secret in a module, a readFile, or a path literal ends up there, and in any cache it is pushed to. Pass a string path to a runtime file instead (for example with systemd LoadCredential), or use a tool like agenix or sops-nix.

Do not bump stateVersion to "upgrade". It records the defaults you started with, for system and for home.

Same path is not always same bytes. A builder that reads the clock or the network can differ run to run. nix-store --realise --check will tell you.

Sandbox is the default on Linux, not on macOS.

A database, secret, or upload is not in the closure. Nix gives you the same program and settings; it does not give you the rows.

A backup you never restored is a hope.

Flakes are still marked experimental. Check the manual for your release; option and flag names move.
