Try It Now, Keep Nothing

Real name: "Your First Encounter with Nix"

You just want to try one thing

Say a friend tells you about a little program that prints a cow saying words. You want to see it. On most computers, that means: find the right place to get it, put it on your machine, and hope it does not break something you already have. Later you will forget it is there. Months on, your computer is full of things you tried once.

This chapter is about a kinder way. You will borrow a program, use it, and hand it back. You will also step into a room with the right tools for a job, then walk out and find your own room untouched. Last, you will make a small thing and look at exactly what changed. No big ideas yet. Just results.

Step one: put the cook in your kitchen

The cook from the last chapter is the tool called Nix. You need it on your computer. The people who make it suggest what they call "multi-user" mode on Linux and on a Mac. In that mode, a helper that keeps running in the background does the building for you, so you do not need special rights each time.

# the install line the Nix site gives for Linux and Mac
curl -L https://nixos.org/nix/install | sh -s -- --daemon

# add --help in place of --daemon to see the other choices

Walk through it. The first part fetches a long list of steps from the web. The second part hands that list to your shell to follow. Any time you do this, it is wise to open the list in your browser first and read it. It will ask to make some changes on your machine, such as new helper users. That is normal for this mode.

  • Linux. The helper mode wants a system that starts its helpers the usual modern way (called systemd), and wants a security layer called SELinux to be off. If your machine is not like that, there is a one-person mode that needs less.
  • Mac. It works, and it is the same line. Some people who upgraded to macOS 15 hit an error about a missing build group. The Nix project has a note on how to mend it, in its issue number 10892.
  • Windows. The usual way is to run Linux inside Windows first, then follow the Linux steps.
  • Anywhere. Close your terminal and open a new one afterward, so it sees the new tool.

Now check that it worked.

nix --version

It prints a name and a number. If you see that, the cook is in. The number will not match mine, and that is fine.

One switch to flipThe newer commands in this chapter are marked by the Nix makers as "experimental", which just means "may still change". Some installs have them off. If a command below says it does not know a feature, run it once like this: nix --extra-experimental-features 'nix-command flakes' …. To keep them on, put the line experimental-features = nix-command flakes in your Nix settings file. Many people find this part annoying, and that is fair.

Step two: borrow a program

nix run nixpkgs#hello

Read it in pieces. nix run means "get this and run it". nixpkgs is the big box of papers from last chapter. The # says which paper in the box. The program is called hello, and all it does is say hello.

The first time, this takes a while, because the cook has to go and get things. The second time is quick. When it ends, hello is not on your list of programs. Type hello by itself and your shell will say it has never heard of it. You borrowed it, and now it is back on the shelf.

Want to use a program more than once, without keeping it? Ask for a little side room:

nix shell nixpkgs#cowsay nixpkgs#lolcat
echo "hello from a borrowed room" | cowsay | lolcat
exit
cowsay          # now it is gone again

Line one opens a new shell with those two programs placed where your shell looks. Line two uses them. exit leaves the room. After that, the last line fails, because the room and its programs are gone from your view.

Step three: a room with the right tools

Remember the Phoenix helper from chapter one, which needed a certain Elixir and Erlang? Here is a first taste of fixing that. A side room can hold any tools you name.

nix shell nixpkgs#elixir nixpkgs#rustc nixpkgs#cargo
elixir --version
rustc --version
exit

Inside the room, both tool sets answer. Outside, your machine is as it was, with whatever versions it had before. Later chapters teach a better way to write down such a room in a file, so a whole team can step into the same one. There is also a command, nix develop, for rooms that a project describes for itself. For now, the point is only that rooms are cheap to make and cheap to leave.

Step four: make a small thing

nix build nixpkgs#hello
ls -l result
./result/bin/hello

Where run borrowed and used a program, build makes it and leaves it for you. Line two shows that a new item named result now sits in your folder. Line three runs the program through that item. Look closely at line two. result is not the program. It is a pointer, like a sticky note, that says where the program really lives. We will follow that note in the next chapter.

Step five: see what changed

Now be a careful detective. After each step, ask what is different. Here is what to check, and what you should expect to find.

You ranCheck withWhat I expect
nix run …#hellowhich hellonothing found; no new item on your program list
nix shell …echo $PATH inside and outsideinside, extra places at the front; outside, as before
nix build …ls -l in the folderone new pointer named result
all of themls /nixa folder you did not have before, which holds what was fetched

That last row is the quiet part. Everything fetched or made went to one place of Nix's own, not into the folders your other programs use. I am not printing sample output here, since the long names you will see are different on every machine. Run it and read yours.

Try it yourself

Keep a small notebook with three columns: what I ran, what I guessed would change, what really changed.

  1. Run a program with nix run and write down whether it is on your program list afterward.
  2. Open a room with nix shell holding any tool you like. Save echo $PATH from inside and from outside. What is different?
  3. Run nix build on a small package from the big box. What new item is in your folder, and where does it point?
  4. Guess first: if you delete result, is the program gone from your machine? Then test it by listing /nix before and after.

What this does not give you

So far you used papers other people wrote, from a box you did not pick a version of. Ask for hello on another day and you might get a different one. Pinning that down is a later chapter's work. The things you fetched also stay on disk until you ask Nix to clear them, so "keep nothing" really means "keep nothing on your program list". And the room only changes what your shell sees, not your settings files or your data. The next chapter looks at that shelf under /nix and why it is built the way it is.

You can try any program, and leave your machine just as you found it.
