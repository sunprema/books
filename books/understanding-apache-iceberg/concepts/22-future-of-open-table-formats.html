Part V · Making Good Decisions

One Plug for Everyone

The data world calls this: the future of open table formats

Here’s the problem

Remember the drawer full of phone chargers, one odd plug for every brand? Then one round of change came along, and now one port fits almost everything. The shops did not stop competing. They just stopped competing on the plug. They compete on the phone.

Table formats are going through the same change right now. Three rival plugs, Iceberg, Delta and Hudi, are drifting toward one shape. If you pick your plug by who shouted loudest this month, you will be back in the drawer next year.

The idea: the plugs are growing alike

The three formats already stand on the same floor: Parquet files (a common way to pack table rows by column) sitting in cheap object storage (big shared file buckets), with a layer of notes on top that says which files make up the table. Their features are borrowing from each other too. Deletion vectors (small marks that say “skip these rows” without rewriting the file) began in Delta and then became part of Iceberg’s version 3 spec. People have even proposed an Iceberg version 4 with a redesigned metadata tree that a future Delta might share. That one is only a talk in the community, not a plan.

The business side moved the same way. In June 2024 Databricks, which looks after Delta Lake, bought Tabular, the company started by Iceberg’s creators, reportedly for over a billion dollars, saying it wanted the formats to work together. Two months later Snowflake and Dremio gave their Polaris catalog to the Apache Software Foundation. By 2026 every big platform offers managed Iceberg: Amazon S3 Tables with automatic upkeep, Databricks managed Iceberg tables, and Snowflake’s Horizon running on Polaris. So the format is no longer what sets them apart. Their engines, catalogs and day-to-day running are.

How it works: three bridges and one port

First, the bridges that let one copy of data wear more than one label. Apache XTable (still incubating, once called OneTable) translates the notes among Hudi, Delta and Iceberg, in full or step-by-step sync. It never copies the data. UniForm, from Delta Lake, writes Iceberg notes a little after each Delta commit, so Iceberg readers can read a Delta table, read-only.

# XTable: one Hudi table, shown to Iceberg and Delta readers
sourceFormat: HUDI
targetFormats:
  - ICEBERG
  - DELTA
datasets:
  - tableBasePath: s3://lake/sales/orders
    tableName: orders

Second, the port. The fight has moved from formats to catalogs (the front desk that knows where every table is). And the catalogs are settling on one shape, the Iceberg REST catalog spec. Apache Polaris became a top-level Apache project in March 2026 and now speaks Delta too. Databricks Unity Catalog offers the same REST calls and can reach into AWS Glue and Snowflake Horizon. Glue ships a REST adapter. Different front desks, one way to knock on the door.

Where the road is bending. Iceberg version 3 became ready for general use with Iceberg 1.10.0 in September 2025. It adds deletion vectors, row lineage (row IDs that survive compaction), a VARIANT type for loose, semi-structured data, geometry and geography types, nanosecond timestamps, default column values, and partition transforms that take several arguments. Many of these answer what AI and machine-learning teams ask for: governed, versioned training data living on the same tables that analysts use, and one copy reachable from many engines.

Here is the catch. Versions only open one way. A v3 reader can read v2 tables, but a v2 reader cannot read v3 tables, and an upgrade cannot be undone.

-- One line. One way. Every reader and writer must already be v3-ready.
ALTER TABLE lake.sales.orders
SET TBLPROPERTIES ('format-version' = '3');
Design principle

Bet on the spec and the shared ports, not on this quarter’s feature race. A new feature counts only when it is in the open spec, when every engine you run can read and write it, and when you truly need it. Upgrade when all three line up.

Use case: the platform team that waits on purpose

A team keeps its sales tables in Iceberg, behind a catalog that speaks the REST spec. A new release brings VARIANT columns, and the data scientists want them. The platform team lists every engine that touches the table: two read it, one writes it. Only after all three confirm version 3 support do they run the one-way upgrade, table by table, starting with a low-risk one. Meanwhile a Hudi table from another group is shown to Iceberg readers through XTable. One format still owns that table’s writes, and everyone else just reads.

Deciding: how to weigh a new thing

QuestionLean towardTrade-off
Is the feature in the adopted open spec?Yes: plan to use itA single vendor’s extension can fade or lock you in
Can every engine you run read and write it?Yes: upgrade the tableOne v2-only reader gets cut off, with no way back
Do you need it today?Yes: adopt in small stepsIf not, waiting costs little and the support grows
Need two formats side by side?XTable or UniForm bridgesRead-only on one side, and translation can lag the source
Choosing a catalog?One that speaks Iceberg RESTOtherwise the lock-in the open format removed comes back

Watch out for

  • “The format war is over” says too much. Notes and catalogs are converging, but writing across formats is still limited, so one format must own each table’s writes.
  • A feature in the spec is not a feature you can use. Engines adopt versions at different speeds.
  • Treating the catalog as a detail. That is where lock-in lives now.
  • Judging formats by vendor benchmark posts. Roadmaps shift with buyouts and proposals, such as the v4 talk.

Sources: Capital One on format convergence; the 2026 state of catalogs; Apache Iceberg 1.10.0 release notes (Google); Dremio on Iceberg v3; Apache XTable; Delta Lake UniForm; Databricks and Snowflake on Tabular and Polaris; Apache Polaris graduation; Amazon S3 Tables.

Because the plugs are growing alike and the port is shared, you can choose your tools for what they do for you, and change them later without carrying your data to a new house.
