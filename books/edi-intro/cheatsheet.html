The 30-second summary

EDI is an externally-owned schema delivered over an at-least-once transport with a slow asynchronous acknowledgment loop. Archive the raw bytes first, read the delimiters from the envelope, deduplicate on the sender's control numbers before any side effect, validate in three layers (structure, semantics, partner guide), map to a canonical model, and always send an acknowledgment — especially when the document was bad.

Delimiters — read, never assume

The ISA is exactly 106 characters. Element separator = char after ISA. Component = ISA16 (offset 104). Repetition = ISA11 (offset 82). Segment terminator = char at offset 106. EDIFACT declares all of it in UNA, plus a release character for escaping.

Idempotency in one line

Key on (partner, direction, ISA13, GS06, ST02) plus a payload hash. Check it after parsing the envelope and before publishing anything. On a duplicate, re-send the stored acknowledgment — do not stay silent.

Alert on absence, not just errors

Transport and certificate failures create no document, so no error fires. The three alerts that catch them: acknowledgment timeout, volume anomaly, and silence past expected cadence. Store the cadence in the partner profile.

Error classes — retry or not

Retry: transport (1), certificate (2, but alert), downstream system (7).
Never retry: envelope (3), syntax (4), implementation guide (5), mapping (6), business rule (8 — and answer it in the 855, not the 997).

The nine fixtures

Happy path · missing segment · invalid code · bad control number · duplicate · unsupported version · delimiter edge case · partner-rule failure · downstream timeout + replay. For every rejection, assert that nothing was published.
