Chapter ElevenEDI Transport and Security

Four ways to move a document, one rule that applies to all of them: transport tells you the bytes arrived, and nothing more than that.

We have been careful to keep transport out of the pipeline proper. Now let's look at what is actually down there, because the operational failures in EDI concentrate at this layer — and they are the ones that fail silently.

AS2

AS2 (specified in RFC 4130) carries EDI payloads over HTTP or HTTPS. The payload is packaged as MIME and secured with S/MIME — encryption for confidentiality, a digital signature for authenticity, and a hash for integrity. It is the protocol most large retailers name in their onboarding requirements.

What makes AS2 more than "HTTP with certificates" is the MDN — the Message Disposition Notification, its receipt. An MDN can be:

  • signed or unsigned — a signed MDN is what makes the receipt itself verifiable;
  • synchronous, returned on the same HTTP connection, or asynchronous, POSTed later to a URL you supply.

A signed MDN carries a message integrity check computed over the content the receiver got. When the original sender verifies that signed receipt, the exchange has established non-repudiation of receipt (NRR): the partner cannot later claim the document never arrived. That legal property is the reason AS2 persists where a plain HTTPS POST would be simpler.

SFTP

SFTP is the pragmatic majority. It gives you transport security through SSH, and everything else is convention: which directory, which filename pattern, who deletes the file after collection, how often you poll. There is no application-level receipt at all — a successful upload is the only signal, which is exactly why the 997 matters so much on SFTP-based relationships.

The half-written file

A poller that lists a directory and reads whatever it finds will eventually read a file mid-upload and report a truncated document. The fix is a convention both sides honour: the sender writes to a temporary name and renames when complete, since rename is atomic within a filesystem. Agree this during onboarding; discovering it in production costs a weekend.

VANs and API bridges

A VAN presents one connection and delivers into partner mailboxes, absorbing the per-partner protocol work at a per-document cost. From your service's point of view it is simply another transport adapter — which is the right way to build it, so that moving a partner from VAN to direct AS2 is a configuration change rather than a project.

Increasingly there is also an API bridge: a provider exposes REST endpoints and handles AS2, certificates and VAN interconnects behind them. Convenient, and worth noting that it does not change any of chapters 7–10 — the documents, control numbers and acknowledgments are identical. Only the adapter changes.

PGP appears independently of all of these, usually on SFTP relationships, encrypting the file itself rather than the channel. If a partner requires it, decryption is pipeline stage 2's neighbour: after receipt, before archive of the decrypted form — and you should archive both.

Keep transport separate

This is worth restating in concrete terms, because it is the chapter's real lesson. A transport failure — connection refused, certificate expired, disk full on the partner's SFTP server — is retryable, and retrying is usually correct. A document failure — malformed envelope, invalid code — is not, and retrying it wastes the signal that something needs human attention.

If both live behind the same function and the same status column, you cannot express that difference, and every failure gets whichever policy the last person to touch the code preferred.

Certificates expire on a Saturday

The most common AS2 outage is an expired certificate — yours or theirs. It fails at the transport layer, so no document is ever created, so no document-level alert fires, and the first symptom is a partner phoning about missing orders. Monitor certificate expiry dates as first-class operational data, with alerts weeks ahead, not days.

So what did we actually gain?

A transport layer that is pluggable and a clear line between "moved" and "understood". The next chapter takes the uncomfortable fact underneath all of this — that every one of these transports can deliver the same document twice — and builds a pipeline that survives it.
