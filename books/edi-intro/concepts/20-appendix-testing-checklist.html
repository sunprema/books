Appendix DTesting Checklist

Nine fixtures. If all nine pass, the integration will survive its first month; if you only test the first one, it will not.

A partner's sample file is, by construction, the happy path. These are the other eight, each with the behaviour you should assert.

The nine fixtures

1 · Valid happy path

The partner's own sample, unmodified. Assert: accepted, canonical order matches the expected JSON exactly, an AK5*A / AK9*A 997 is generated, one record published downstream.

2 · Missing required segment

Delete the N1 ship-to loop. Assert: rejected at the structural layer, a finding naming N1, an AK5*R 997, and nothing published downstream — the last part is the one that actually matters.

3 · Invalid code or qualifier

Change a unit of measure to BX when the profile allows only CA/EA/PL. Assert: rejected at the partner-guide layer, not the syntax layer, and the finding names the rule (acme-retail/uom-allowed) so the message can be sent to the partner as-is.

4 · Incorrect control number

Make IEA02 disagree with ISA13, then separately make SE01 off by one. Assert: the first produces a TA1-class envelope failure; the second a syntax failure. Two different classes, two different acknowledgments — appendix C in action.

5 · Duplicate document

Submit fixture 1 twice, byte-identical. Assert: the second returns duplicate, publishes nothing, and re-sends the stored 997. Then submit a third copy with the same control numbers but a changed line quantity: the payload hash differs, so this must not be treated as a duplicate.

6 · Unsupported version

Set GS08 to 004010 when the profile declares 005010. Assert: rejected with a clear version-mismatch finding — not a cascade of forty segment errors from validating against the wrong rule set.

7 · Delimiter edge case

Two variants. First, re-emit fixture 1 with | as the element separator and a newline terminator: assert it parses identically, proving delimiters are read from the ISA. Second, put the element separator inside a PID description: assert it is escaped, rejected or substituted — but never silently shifts the elements after it.

8 · Partner-specific rule failure

Omit REF*DP when the profile sets requireDeptRef. Assert: rejected — and, importantly, that the same document passes under a second partner profile without that rule. This is what proves the rules are configuration and not baked into the shared path.

9 · Downstream timeout and replay

Make publish() throw after the deduplication check has recorded the document. Assert: the failure is classed retryable; then replay from the archive and confirm exactly one order exists downstream at the end. This is the test that proves chapters 7 and 12 actually work together.

Golden files for the outbound side

The nine above test the parser. The generator needs its mirror: for each transaction set you emit, a fixture pairing a canonical document with the exact reviewed bytes, asserted byte-for-byte.

Pin the non-determinism

Golden files only work if the clock and the control-number allocator are injected. A generator that reads now() internally produces a test that fails at midnight and a control number that drifts every run — and a test people learn to re-bless without reading the diff is worse than no test.

Before certification

  • All nine parser fixtures pass, and each asserts what was not done as well as what was.
  • Golden files exist for every outbound transaction set, per partner.
  • ISA15 is T in every test fixture and configuration.
  • The silence and acknowledgment-timeout alerts are wired and have been observed firing at least once deliberately.
  • The support screen can find a document by control number and by PO number, and can show the raw payload.
Assert the negative

The recurring theme of this list: for every rejection test, assert that nothing was published downstream. A validator that correctly reports an error and then publishes the order anyway passes a naive test suite and causes an incident — and it is a surprisingly easy mistake to make when the validation result is a warning-shaped return value rather than a control-flow branch.

That is the book. You now have the envelopes, the flows, the pipeline, the idempotency, the operational signals, and the tests that keep them honest. The rest is one partner at a time.
