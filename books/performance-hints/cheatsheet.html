Cheatsheet

The 30-second version

Estimate before you build, measure before you change. Then work down the ladder: interface shape → algorithm → memory layout → allocation count → work skipped. A flat profile means diffuse cost, not optimal code.

Worked estimates to reason from

  • Quicksort 1e9 4-byte numbers: ~7.5 s memory traffic + ~75 s branch mispredicts = ~82.5 s.
  • 30 thumbnails: serial disk ~450 ms · parallel disk ~15 ms · SSD ~30 ms.

Measurement

Instruments

  • pprof first — locally and in production.
  • Build production binaries with debug info.
  • Microbenchmark the code you're changing; emit hardware counters.
  • Lock contention lowers CPU usage. Low CPU + high latency → look at contention, not the CPU profile.

When the profile is flat

  • Accumulate many 1% wins across a subsystem.
  • Find loops near the top of call stacks.
  • Look for structural changes, not micro ones.
  • Replace over-general code with specialized code.
  • Allocation-profile to cut allocation counts.
  • Hardware counters to find cache misses.

The checklist

Interfaces

  • Bulk APIs — one boundary crossing, one lock, and the callee can finally see the whole request.
  • View types — string_view, Span, FunctionRef. No copy, any container.
  • Take precomputed args the caller already holds (clock, hash, length).
  • Thread-compatible by default; internal locking only when it's nearly always needed.

Algorithms

  • Highest leverage in the book. A curve beats a constant factor at any scale that matters.
  • Build in bulk so you can choose an order (ranks → cycle detection is a comparison).
  • O(log N) → O(1) by hashing; sorted-list intersection → hash and probe.
  • Look for: nested loops over one collection, linear search per element, order you never use.

Memory representation

  • Goal, always: touch fewer cache lines.
  • Group fields by alignment to kill padding; size enums (: uint8_t).
  • Hot fields adjacent; hot-read apart from hot-write; cold data moved away.
  • Indices instead of pointers: smaller references and contiguous elements.

Containers

  • Flat/chunked over node-based: vector, flat_hash_map.
  • InlinedVector when counts are small and instances are many.
  • Flatten map<a, map<b, c>> to map<pair<a,b>, c>.
  • Arenas for structures with many sub-objects; give a sane initial size.
  • Small integer keys → array. Small-domain membership → bit vector (26–31% measured).

Allocations

  • Three bills: allocator time, init/destroy, and a fresh cache line each.
  • Share one static empty instance (21% throughput in the document's benchmark).
  • reserve once with the total, never one element at a time.
  • Move, don't copy; store pointers/indices (one removed copy = 10–15%).
  • Hoist the temporary out of the loop and Clear() it; offer a scratch parameter.

Unnecessary work

  • Fast path for the common case — and keep it small (icache).
  • A "nothing to do" flag beats the loop it guards.
  • Precompute invariants once; hoist loop-invariant work out.
  • Defer until needed (43 s → 2 s); compute stats on demand; don't pre-build 200 of anything (7.5%).
  • Specialize where the profile says so (custom histogram print ≈ 4× sprintf).
  • Cache on a cheap fingerprint.
