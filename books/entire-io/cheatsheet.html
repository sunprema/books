The 30-Second Summary

What Entire Does

Entire.io is a CLI tool that turns ephemeral AI agent coding sessions into durable, searchable, git-native engineering context. When you use an AI coding agent (Claude Code, Cursor, GitHub Copilot), the session ends and the reasoning vanishes. Git records what changed. Entire records why and how. It captures the full conversation, tool calls, and decision-making context, then stores it in a dedicated branch of your Git repository.

Core Concepts

Session

A recorded unit of agent work. One session = one conversation between a developer and an AI coding agent. The session captures prompts, agent responses, tool calls (file reads, searches, test runs), and reasoning. Sessions are the atomic unit of context in Entire.

Checkpoint

A save point within a session. A checkpoint snapshots the state of both the code and the conversation at a specific moment. Think of it as a bookmark that captures not just where you are in the code, but where you are in the reasoning. You can have multiple checkpoints per session.

Commit Linkage

Each checkpoint is linked to the Git commits it produced. This creates a bidirectional connection: from a commit, you can find the session and reasoning that produced it; from a session, you can find the commits that resulted. The diff tells you what changed. The linked session tells you why.

Checkpoint Branch

A dedicated Git branch (e.g., entire/checkpoints) where session metadata is stored. This branch does not contain your application code — it contains the session transcripts, checkpoint data, and linkage information. It lives alongside your code in the same repository, versioned and backed up by Git, but separate from your working branches.

Workflow Patterns

Solo Developer

Use Entire as a personal engineering journal. Checkpoint at decision points. Future-you will thank present-you when returning to code written weeks ago and wondering "why did I choose this approach?"

Team size
1
Primary benefit
Personal context recall
Checkpoint frequency
At decision points and before risky changes

Team / Feature Branch

Session transcripts accompany pull requests. Reviewers see not just the diff but the prompt, constraints, reasoning, and tool calls. Code review shifts from "does this look right?" to "does this match the intent?"

Team size
3 - 8
Primary benefit
Intent-aware code review
Checkpoint frequency
Before opening a PR; at major decision points

Agent Handoff

When one agent's session ends and another begins, the checkpoint carries context across the boundary. The second agent (or developer) starts with the full history of what was tried, what worked, and what was decided — not from zero.

Team size
2+
Primary benefit
No context loss at boundaries
Checkpoint frequency
At every handoff point

Research / Exploration

Exploratory coding where the journey matters as much as the destination. Even sessions that produce no code are valuable — they capture what you tried, what failed, and why you decided against an approach.

Team size
1 - 4
Primary benefit
Capturing the journey, not just the result
Checkpoint frequency
After significant findings or dead ends

When to Checkpoint

Situation Checkpoint? Why
Completed a logical unit of work Yes Natural save point; reasoning is coherent and complete
About to try a risky refactor Yes Save point for recovery if the refactor goes wrong
Chose between multiple approaches Yes Captures the decision and the alternatives considered
Explored and decided NOT to proceed Yes Captures why; prevents others from re-exploring
About to hand off to another agent or developer Yes Transfers full context across the boundary
Before opening a pull request Yes Gives reviewers access to the reasoning
Fixed a typo or bumped a version No Diff is self-explanatory; no reasoning to capture
Non-agent manual coding No No agent session to capture
Throwaway / one-off script No Code will not be maintained; context has no future value

Privacy Quick Reference

Data Handling Rules

Always safe to capture
Prompts, agent reasoning, tool call sequences, file paths, test results
Context-dependent
Source code snippets, internal URLs, architecture discussions, config values
Must redact before checkpoint
API keys, database credentials, auth tokens, customer PII
Never capture
Production secrets, encryption keys, regulated data (HIPAA/PCI/GDPR), production database contents

Public vs. Private Repos

Private repo
Capture broadly, redact secrets. Checkpoint branch is visible to anyone with repo access.
Public repo
Capture selectively, redact aggressively. Checkpoint branch is world-readable.

The Four Layers of Review Context

Review with Intent

Layer 1 — Diff
Lines changed. What traditional review sees.
Layer 2 — Reasoning
Tool calls, alternatives explored, decisions made.
Layer 3 — Constraints
Boundaries and requirements specified in the prompt.
Layer 4 — Intent
The original goal. The "why."

Start with the prompt (Layer 4), skim tool calls (Layer 2), then read the diff (Layer 1) with intent in mind. This is faster than reading the diff cold.

Adoption Checklist

Three Questions Before Adopting

  1. Is the code agent-generated? If yes, you are losing context by default.
  2. Will someone else read this code? If yes, durable context helps them.
  3. Is the reasoning non-obvious? If yes, the "why" has lasting value.

Three "yes" answers: strong fit. Two: worth trying. One or zero: skip it for that workflow.

The Big Picture

From Recording to Reasoning Infrastructure

Today, Entire captures session context. Tomorrow, that context becomes queryable — agents that learn from past sessions, semantic search over reasoning, cross-project knowledge sharing. The shift: from "code as artifact" to "code as one layer of a richer knowledge graph."
