Chapter 11 · Part IV — Replacing a File Safely

Metadata Fidelity

Recall fact four from chapter 2: a clone arrives with its own copy of the source's attributes and extended attributes. That is a sensible default for “make me a copy of this file.” It is exactly wrong for “make me a replacement for that other file.” The clone we hand the user has the source's permissions, the source's Finder tags, the source's icon — and the user is expecting their own file. This chapter is the 466 lines that fix that.

The goal, stated by the module itself

src/apfs/metadata.rsthe module doc comment, verbatim

//! Snapshot and restore of the target-specific metadata that must survive a
//! replacement: permissions, ownership, timestamps, BSD flags, extended
//! attributes (which carry Finder info, tags, and the resource fork), and
//! ACLs. The clone starts with the *source's* metadata; restoring the
//! snapshot makes it indistinguishable from the target it replaces.

Indistinguishable is a demanding word, and it is the right bar. If the replacement has a different modification date, every backup tool on the machine thinks the file changed. If it loses a Finder tag, the user's carefully colour-coded folder is quietly wrong. If it loses an ACL, someone may gain or lose access. A space-saving tool that costs you your metadata has not saved you anything.

What gets captured

src/apfs/metadata.rsverbatim

/// Everything we capture from a target before replacing it.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct MetadataSnapshot {
    /// Permission bits including setuid/setgid/sticky (`st_mode & 0o7777`).
    pub mode: u32,
    pub uid: u32,
    pub gid: u32,
    /// BSD flags (`st_flags`): UF_HIDDEN, UF_IMMUTABLE, …
    pub flags: u32,
    pub atime: (i64, i64),
    pub mtime: (i64, i64),
    /// Birth time; restored via `setattrlist` where possible.
    pub crtime: Option<(i64, i64)>,
    /// All extended attributes, sorted by name. Includes
    /// `com.apple.FinderInfo` and `com.apple.ResourceFork`.
    pub xattrs: Vec<(String, Vec<u8>)>,
    /// ACL in text form, `None` when the file has no ACL.
    pub acl_text: Option<String>,
}

Two type choices tell you about macOS. crtime is an Option, because the birth time — the date a file was created, which macOS tracks and most Unixes do not — is not always available; None means “there was nothing to restore,” which is different from “we failed.” And xattrs is a Vec<(String, Vec<u8>)>: names are text, values are arbitrary bytes. A Finder tag is a binary property list; a resource fork can be megabytes. Neither is a String, and pretending otherwise would corrupt them.

The snapshot is taken with one stat, one xattr enumeration and one ACL read, and its PartialEq derive means a test can snapshot two files and assert the metadata round-tripped exactly.

Timestamps as pairs

(i64, i64) is seconds and nanoseconds — the shape of a timespec, which is what the syscalls want. It is a small concession to the C boundary, and it is honest: nanosecond precision is exactly what verify_unchanged and the executor's race check compare on, so throwing it away here would defeat them.

Restore that is allowed to partially fail

src/apfs/metadata.rsverbatim

/// What a restore actually accomplished. Ownership and ACL restoration can
/// legitimately fail without privileges; the caller decides whether partial
/// fidelity is acceptable before committing the swap.
#[derive(Debug, Default, Clone, PartialEq, Eq)]
pub struct RestoreOutcome {
    pub ownership_restored: bool,
    pub crtime_restored: bool,
    pub warnings: Vec<String>,
}

This little struct encodes a real-world truth. Restoring uid/gid requires privileges an ordinary user does not have, and a file owned by someone else is a perfectly normal thing to find in a scan. If that made the whole transaction fail, the tool would be useless in exactly the directories people most want to clean.

So the module splits its failures in two. Mode, xattrs and timestamps are hard — if they cannot be restored, return Err and the transaction rolls back. Ownership, ACL and birth time are soft — record a warning and carry on. Those warnings travel out through TxnReport.warnings and the CLI prints them:

src/main.rsinside run_reclaim, verbatim

                for warning in &report.warnings {
                    println!("      warning: {warning}");
                }

The doc comment's phrasing is careful: the caller decides whether partial fidelity is acceptable. Today the caller accepts it and reports it. A future GUI could offer to stop. The policy is not baked into the mechanism, which is why the mechanism returns a struct instead of a bool.

The order is the design

Here is the top of restore. Read the doc comment first — it is four lines and it is the entire chapter:

src/apfs/metadata.rsverbatim

    /// Reapply a snapshot to `path` (the fresh clone). Hard failures on
    /// mode/xattrs/times return `Err`; ownership, ACL, and birth-time
    /// restoration degrade to warnings because they can require privileges
    /// the process legitimately lacks.
    ///
    /// Order matters: xattrs and ACL first, then ownership (chown clears
    /// setuid bits), then mode, then times (earlier steps touch them), and
    /// BSD flags last — an immutable flag would block every other step.
    pub fn restore(path: &Path, snap: &MetadataSnapshot) -> io::Result<RestoreOutcome> {
        let mut outcome = RestoreOutcome::default();

        // Xattrs: remove strays inherited from the source, then write the
        // target's set.
        let wanted: std::collections::HashSet<&str> =
            snap.xattrs.iter().map(|(n, _)| n.as_str()).collect();
        for existing in list_xattrs(path)? {
            if !wanted.contains(existing.as_str()) {
                remove_xattr(path, &existing)?;
            }
        }
        for (name, value) in &snap.xattrs {
            set_xattr(path, name, value)?;
        }

Removing the strays

The first thing restore does is delete. Because the clone inherited the source's extended attributes, it may be carrying attributes the target never had — the source's Finder tag, the source's Spotlight comment, the source's resource fork. Copying the target's xattrs on top would leave those extras in place, and the replacement would be a file with a stranger's tags on it.

So the code builds a HashSet of the names the target had, lists what the clone currently has, and removes anything not wanted — then writes the target's set. The HashSet<&str> borrows the names out of the snapshot rather than cloning them, which is a nice small instance of “a set of references is still a set.”

The integration test for this is pointed: the stand-in file is given an xattr called user.stray-from-source that the target does not have, and the test asserts it is gone afterwards. The name is the documentation.

chown before chmod

This is a classic Unix trap. chown clears the setuid and setgid bits — deliberately, because transferring a setuid binary to a new owner would otherwise be a privilege-escalation gift. So if you restore the mode first and the ownership second, you silently lose those bits. Restore ownership first, mode second, and the bits land last and survive. The code does exactly that, and it also avoids the syscall entirely when it can:

src/apfs/metadata.rsverbatim

        let meta = std::fs::symlink_metadata(path)?;
        if meta.uid() == snap.uid && meta.gid() == snap.gid {
            outcome.ownership_restored = true;
        } else {
            let c_path = cpath(path)?;
            let rc = unsafe { libc::lchown(c_path.as_ptr(), snap.uid, snap.gid) };
            if rc == 0 {
                outcome.ownership_restored = true;
            } else {
                let err = io::Error::last_os_error();
                outcome.warnings.push(format!(
                    "ownership not restored to {}:{}: {err}",
                    snap.uid, snap.gid
                ));
            }
        }

If the clone already has the right owner — the overwhelmingly common case, since both files usually belong to the user running the tool — nothing is called at all and ownership_restored is simply true. Only when they differ does it attempt lchown (the l is “do not follow symlinks,” the same discipline as everywhere else), and a failure there becomes a warning naming the uid and gid it wanted.

Then mode, times, and flags

src/apfs/metadata.rsverbatim &mdash; restore(), steps 3 and 4a

        let c_path = cpath(path)?;
        let rc = unsafe { libc::chmod(c_path.as_ptr(), snap.mode as libc::mode_t) };
        if rc != 0 {
            return Err(io::Error::last_os_error());
        }

        match set_crtime(path, snap.crtime) {
            Ok(restored) => outcome.crtime_restored = restored,
            Err(err) => outcome
                .warnings
                .push(format!("birth time not restored: {err}")),
        }

src/apfs/metadata.rsverbatim &mdash; restore(), steps 4b and 5

        let times = [
            libc::timespec {
                tv_sec: snap.atime.0,
                tv_nsec: snap.atime.1,
            },
            libc::timespec {
                tv_sec: snap.mtime.0,
                tv_nsec: snap.mtime.1,
            },
        ];
        let rc = unsafe {
            libc::utimensat(
                libc::AT_FDCWD,
                c_path.as_ptr(),
                times.as_ptr(),
                libc::AT_SYMLINK_NOFOLLOW,
            )
        };
        if rc != 0 {
            return Err(io::Error::last_os_error());
        }

        if snap.flags != 0 {
            // chflags follows symlinks, but restore only ever runs on the
            // temp clone we just created, which is a regular file.
            let rc = unsafe { libc::chflags(c_path.as_ptr(), snap.flags) };
            if rc != 0 {
                return Err(io::Error::last_os_error());
            }
        }

        Ok(outcome)
    }

chmod is hard-fail: a replacement with the wrong permissions is not acceptable, and chapter 10's temp verification double-checks the mode afterwards for exactly this reason.

utimensat takes a two-element array — access time then modification time — and AT_FDCWD means “interpret the path relative to the current directory,” which for an absolute path is a formality. It comes after everything else because every preceding operation touches the modification time; setting it first would be immediately undone.

chflags is last and conditional. If the target had BSD flags — hidden, locked — they go on now, because setting an immutable flag any earlier would lock the file against every step that follows. The comment addresses the one wart: chflags has no l variant, so it follows symlinks — and the code explains why that cannot bite here, since restore only ever runs on a temp clone it just created itself. That is the right way to handle an unavoidable sharp edge: not by ignoring it, but by writing down why it is blunt in this context.

The ask-then-read pattern, with a retry

Reading a list of extended attributes is the canonical example of a C API that hands you a buffer-sizing problem. You ask how big, allocate, then ask again for real:

src/apfs/metadata.rsverbatim

    pub(super) fn list_xattrs(path: &Path) -> io::Result<Vec<String>> {
        let c_path = cpath(path)?;
        loop {
            let size = unsafe {
                libc::listxattr(
                    c_path.as_ptr(),
                    std::ptr::null_mut(),
                    0,
                    libc::XATTR_NOFOLLOW,
                )
            };
            if size < 0 {
                return Err(io::Error::last_os_error());
            }
            if size == 0 {
                return Ok(Vec::new());
            }
            // …the second call, into a buffer of that size…

src/apfs/metadata.rsverbatim &mdash; the read, the ERANGE retry, and the parse

            let mut buf = vec![0u8; size as usize];
            let read = unsafe {
                libc::listxattr(
                    c_path.as_ptr(),
                    buf.as_mut_ptr().cast(),
                    buf.len(),
                    libc::XATTR_NOFOLLOW,
                )
            };
            if read < 0 {
                let err = io::Error::last_os_error();
                // The list grew between the two calls; retry.
                if err.raw_os_error() == Some(libc::ERANGE) {
                    continue;
                }
                return Err(err);
            }
            buf.truncate(read as usize);
            return Ok(buf
                .split(|&b| b == 0)
                .filter(|name| !name.is_empty())
                .map(|name| String::from_utf8_lossy(name).into_owned())
                .collect());
        }
    }

The loop is the part most people leave out. Between the sizing call and the reading call, another process can add an attribute — and the kernel then returns ERANGE because the buffer no longer fits. The obvious code treats that as an error; this code treats it as “the world moved, ask again.” The same pattern, with the same retry, appears in get_xattr just below it.

The parsing tail is a nice piece of iterator work. listxattr returns names packed as NUL-separated bytes, so: split on zero bytes, filter out the empty slice left by the trailing separator, and map each to an owned String with from_utf8_lossy — lossy, because an attribute name that is not valid UTF-8 should not crash a scan.

buf.as_mut_ptr().cast() is worth a glance too: .cast() converts *mut u8 to the *mut c_void the signature wants. It is as-casting for pointers, but restricted to pointer-to-pointer conversions — a small, sharp tool instead of a blunt one.

Binding a C API the libc crate does not have

Darwin's ACL functions are not in the libc crate. Rather than adding a dependency, the module declares the six functions it needs:

src/apfs/metadata.rsverbatim

    // The libc crate does not bind Darwin's ACL API; declare what we use.
    type AclT = *mut libc::c_void;
    const ACL_TYPE_EXTENDED: libc::c_uint = 0x100;

    unsafe extern "C" {
        fn acl_get_link_np(path: *const libc::c_char, acl_type: libc::c_uint) -> AclT;
        fn acl_set_link_np(
            path: *const libc::c_char,
            acl_type: libc::c_uint,
            acl: AclT,
        ) -> libc::c_int;
        fn acl_to_text(acl: AclT, len_p: *mut libc::ssize_t) -> *mut libc::c_char;
        fn acl_from_text(text: *const libc::c_char) -> AclT;
        fn acl_init(count: libc::c_int) -> AclT;
        fn acl_free(obj: *mut libc::c_void) -> libc::c_int;
    }

An extern "C" block is a promise: “these functions exist in some library I will be linked against, with these signatures.” The compiler cannot check it. Get a type wrong — say c_int where the real API takes a c_uint — and you get undefined behaviour, not an error. That is why the whole block sits inside the apfs module and why every declaration mirrors the system header exactly. In the Rust 2024 edition the block itself is written unsafe extern "C", making the promise explicit at the declaration site.

The ACL is handled as text: read it with acl_get_link_np, convert to a string with acl_to_text, and later parse it back with acl_from_text. That is a pragmatic choice — the textual form is stable and human-readable, and it avoids modelling ACL entries in Rust at all.

Two subtleties in the reading code are worth naming. The first is an error code that means something surprising:

src/apfs/metadata.rsinside get_acl_text, verbatim

        let acl = unsafe { acl_get_link_np(c_path.as_ptr(), ACL_TYPE_EXTENDED) };
        if acl.is_null() {
            let err = io::Error::last_os_error();
            // ENOENT here means "no ACL", not "no file".
            return match err.raw_os_error() {
                Some(libc::ENOENT) => Ok(None),
                _ => Err(err),
            };
        }

A file with no ACL reports ENOENT — “no such file or directory” — which is exactly the sort of thing you only learn by being burned. Mapping it to Ok(None), with a comment, is the difference between working code and a mystery bug.

The second is memory management. These C functions allocate, and Rust will not free their memory for you, so every path calls acl_free — including the text buffer returned by acl_to_text, which is a separate allocation from the ACL itself. The code computes a result value first and frees afterwards, so that the cleanup runs on both the success and failure paths. That is the manual equivalent of a destructor, and forgetting it is how long-running processes leak.

Restoring has one more wrinkle, and it is the same idea as removing stray xattrs:

src/apfs/metadata.rsinside set_acl_text, verbatim

            // No ACL on the target: install an empty one so nothing
            // inherited from the source survives.
            None => {
                let acl = unsafe { acl_init(0) };
                if acl.is_null() {
                    return Err(io::Error::last_os_error());
                }
                acl
            }

“The target had no ACL” cannot be implemented as “do nothing,” because the clone may have inherited one from the source or from the directory. It has to be implemented as “install an empty ACL.” Absence has to be applied, not skipped — a rule worth remembering any time you are restoring state.

Birth time, via setattrlist

There is no portable way to set a file's creation date. macOS offers setattrlist, which takes a bitmap describing which attributes you are setting and a buffer holding their values — and which is also not in the libc crate. So the module declares the struct and the function:

src/apfs/metadata.rsverbatim

    #[repr(C)]
    struct AttrList {
        bitmapcount: u16,
        reserved: u16,
        commonattr: u32,
        volattr: u32,
        dirattr: u32,
        fileattr: u32,
        forkattr: u32,
    }

    const ATTR_BIT_MAP_COUNT: u16 = 5;
    const ATTR_CMN_CRTIME: u32 = 0x0000_0200;
    const FSOPT_NOFOLLOW: u32 = 0x1;

#[repr(C)] is mandatory here and it is the whole reason this works. By default, Rust reserves the right to reorder struct fields for packing; a C API reading this memory expects the fields in declaration order with C's padding rules. #[repr(C)] pins that layout. Leave it off and you have a struct that compiles fine and hands the kernel garbage.

src/apfs/metadata.rsverbatim

    /// Restore the birth time. Returns Ok(false) when the snapshot has no
    /// birth time to restore.
    fn set_crtime(path: &Path, crtime: Option<(i64, i64)>) -> io::Result<bool> {
        let Some((sec, nsec)) = crtime else {
            return Ok(false);
        };
        let c_path = cpath(path)?;
        let attrs = AttrList {
            bitmapcount: ATTR_BIT_MAP_COUNT,
            reserved: 0,
            commonattr: ATTR_CMN_CRTIME,
            volattr: 0,
            dirattr: 0,
            fileattr: 0,
            forkattr: 0,
        };
        let mut when = libc::timespec {
            tv_sec: sec,
            tv_nsec: nsec,
        };
        let rc = unsafe {
            setattrlist(
                c_path.as_ptr(),
                (&raw const attrs).cast(),
                (&raw mut when).cast(),
                std::mem::size_of::<libc::timespec>(),
                FSOPT_NOFOLLOW,
            )
        };
        if rc != 0 {
            return Err(io::Error::last_os_error());
        }
        Ok(true)
    }

The return type says something precise: Ok(false) means “there was nothing to restore,” Ok(true) means “restored,” and Err means “tried and failed” — which the caller turns into a warning. Three outcomes, no ambiguity.

And (&raw const attrs).cast() is modern Rust worth adopting. The raw-borrow operators &raw const and &raw mut create a raw pointer without first creating a reference. The older spelling, &attrs as *const _, briefly materialises a & — which carries aliasing guarantees that can be violated in FFI contexts. Same machine code, fewer footguns, and it reads as what it is: give me the address.

The resource fork, once more

Chapter 4 read the fork's length at scan time. The transaction needs its contents, and forks.rs gets them by reusing the xattr reader:

src/apfs/forks.rsverbatim

/// Full resource-fork contents; empty when the file has none.
#[cfg(target_os = "macos")]
pub fn read_resource_fork(path: &Path) -> io::Result<Vec<u8>> {
    match crate::apfs::metadata::darwin_get_xattr(path, RESOURCE_FORK_XATTR) {
        Ok(data) => Ok(data),
        Err(err) if err.raw_os_error() == Some(libc::ENOATTR) => Ok(Vec::new()),
        Err(err) => Err(err),
    }
}

/// Byte-for-byte resource-fork comparison. Files identical "in the macOS
/// sense" must match here as well as in their data forks.
pub fn resource_forks_equal(a: &Path, b: &Path) -> io::Result<bool> {
    Ok(read_resource_fork(a)? == read_resource_fork(b)?)
}

The same shape as the ACL's ENOENT: a specific error code — ENOATTR, “attribute not found” — is not a failure but a value, the empty fork. The match guard Err(err) if … is exactly the right tool: match on one error and let every other one through untouched.

Because a fork is just an xattr, the restore path gets it for free — it is one of the entries in snap.xattrs. The dedicated reader exists for the comparison in chapter 10's identity check, where a fork must be compared byte for byte independently of the data fork.

The round trip, tested

The integration test builds a target with distinctive metadata, snapshots it, and restores onto a stand-in that has been deliberately made wrong in every dimension:

tests/apfs_integration.rsabridged &mdash; the assertions after the restore are elided

    // Give the target distinctive metadata.
    fs::set_permissions(&target, fs::Permissions::from_mode(0o640)).unwrap();
    set_xattr(&target, "com.apple.metadata:_kMDItemUserTags", b"bplist-tags");
    set_xattr(&target, "user.custom", b"target-specific");
    forks_set(&target, b"target resource fork");
    let mtime = SystemTime::UNIX_EPOCH + Duration::from_secs(1_234_567_890);
    // …set the target's mtime…

    let snap = metadata::snapshot(&target).unwrap();
    assert_eq!(snap.mode, 0o640);
    assert_eq!(snap.xattrs.len(), 3);
    assert!(snap.acl_text.is_none());

    // A stand-in for the fresh clone: different mode, a stray xattr the
    // target does not have, no fork, wrong times.
    let temp = dir.path().join("stand-in.doc");
    fs::write(&temp, b"target content").unwrap();
    fs::set_permissions(&temp, fs::Permissions::from_mode(0o755)).unwrap();
    set_xattr(&temp, "user.stray-from-source", b"should vanish");

A Finder tag, a custom xattr, a resource fork, a specific mode, a specific mtime — and a stand-in carrying a stray attribute whose name announces what it is testing. The assertions that follow check that all three of the target's attributes arrived, the mode is 0o640 again, the mtime is what it was, and user.stray-from-source is gone.

That last one is the assertion the whole module exists for. Anyone can copy metadata onto a file. Removing what should not be there is the part people forget.

So what did we actually gain?

A replacement your Mac cannot tell from the original. Same permissions, same owner where we are allowed, same access, modification and creation times, same Finder tags and comments, same resource fork, same ACL, same BSD flags — and, crucially, nothing extra inherited from the source. Only the inode number and the physical blocks are different, and those are the two things the user was never looking at.

The transferable lessons are about restoring state generally: absence is a value that must be applied, not skipped; ordering is a dependency graph, not a preference; ask-then-read needs a retry; and a partial success is worth reporting rather than either hiding or fataling on. This module is 466 lines and roughly a third of them are comments explaining why a line is where it is. On code this sharp, that ratio is correct.

Challenges
  1. Swap the chmod and chown steps and write the test that catches it. Which bits does it have to check, and what permissions does the test need to run?
  2. acl_text stores the ACL as a string produced by acl_to_text. What breaks if a future macOS changes that textual format between the snapshot and the restore — and does the transaction still fail safe?
  3. The snapshot captures atime and restores it. Given that reading a file updates its access time, argue whether restoring it is worth the syscall.
