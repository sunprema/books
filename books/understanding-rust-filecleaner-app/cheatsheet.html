Quick reference

FileCleaner Cheatsheet

Everything from the twelve chapters, dense enough to keep open beside the source tree. Paths are relative to the repository root of sunprema/file_cleaner.

The 30-second summary Find byte-identical files on one APFS volume. Never delete: replace each duplicate with a clonefile clone of a chosen source, staged as a hidden sibling, wearing the target's restored metadata, swapped in by two atomic renames, with each journal state made durable before the filesystem step it precedes — so a crash is repaired on the next launch by rolling back before the swap point and forward after it.

The CLI

filecleaner scan <dirs...>              # index files + run the funnel
filecleaner scan --include-packages …   # also enter .app / .photoslibrary bundles
filecleaner scans                       # list scan sessions
filecleaner groups                      # groups from the latest scan
filecleaner groups --scan <id>          # groups from an older scan
filecleaner reclaim --group <id>        # DRY RUN (the default) — changes nothing
filecleaner reclaim --group <id> --confirm   # actually replace the targets
--db <path>    (any command)            # default: ~/.filecleaner/index.db
--json         (any command)            # machine-readable output for a GUI

Recovery of any interrupted transaction runs before every one of these, automatically, and prints a recovered: … line per repair.

The funnel

1Bucket by (dev, size, rsrc_len) in SQL, HAVING COUNT(DISTINCT ino) >= 2. Zero bytes read.
2BLAKE3 over first/middle/last 64 KiB (RANGE_LEN); whole file if ≤ 192 KiB. ≤ 192 KiB per file.
3Streaming SHA-256 in 1 MiB chunks — the stored identity. Whole file.
4Byte-for-byte comparison of both forks, inside the transaction. The only authority.

Stages 1–3 persist their results and only select rows whose column IS NULL — so a re-run resumes instead of rehashing. Every read is preceded by verify_unchanged; a changed file becomes HashError::Stale and drops out of the funnel (counted, never fatal).

The transaction, step by step

preflight                                  (10 read-only checks)
journal `prepared`
  snapshot target metadata
  byte-compare data forks + resource forks   <-- final authority
  clonefile(source -> temp)                  Progress::TempCreated
  restore target metadata onto temp
  verify temp: type, size, mode, bytes, fork
journal `backup-created`
  rename(target -> backup)                   Progress::BackupRenamed
  re-stat backup vs. scan expectations       <-- closes the verify-to-swap race
journal `swapped`
  rename(temp -> target)                     Progress::TargetSwapped
  fsync(dir)
  final validation: type, size, bytes
  remove backup                              (failure here = warning, not rollback)
journal `committed`

Rollback is chosen from Progress, not from what is on disk. Once run() returns Ok, nothing rolls back — leftover work becomes a warning saying recovery will finish it.

Journal states & recovery

StateWritten beforeRecovery does
preparedeverything up to the first renamedelete any temp → rolled-back
backup-createdrename(target, backup)restore backup if target missing, delete temp → rolled-back
swappedrename(temp, target)roll forward: finish the rename, remove backup → committed; if the clone was lost, restore the backup instead
committed—terminal — ignored
rolled-back—terminal — ignored

Legal edges only: prepared→backup-created→swapped→committed, plus any non-terminal state →rolled-back. Illegal transitions are rejected by Db::journal_set_state, not merely by convention. Recovery runs on every launch and is idempotent.

Rust idioms used here

Newtype over a primitive

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct VolumeId(pub u64);        // a u64 at runtime, a distinct type at compile time

A closure that must own its capture

let source_ino = self.source().ino;
self.members.iter().filter(move |m| m.ino != source_ino && m.nlink == 1)
// `move` copies the u64 in, so the returned iterator outlives the local

A policy as one tuple comparison

let candidate_key = (candidate.mtime_sec, candidate.mtime_nsec, &candidate.path);
// tuples compare lexicographically: oldest second, then nanosecond, then path

Counting inside an Fn closure

let packages_skipped = Cell::new(0u64);          // single-threaded interior mutability
packages_skipped.set(packages_skipped.get() + 1);
// thread-safe variant, when the trait demands Send + Sync:
let call = self.fork_calls.fetch_add(1, Ordering::SeqCst) + 1;

let–else and let chains

let Ok(c_path) = CString::new(path.as_os_str().as_bytes()) else { return 0; };
if let Some(parent) = path.parent() && !parent.as_os_str().is_empty() { … }
// the second needs edition 2024 (let chains, stable since Rust 1.88)

Typed errors, and ? conversions

#[derive(Debug, thiserror::Error)]
pub enum HashError {
    #[error("file changed since scan")]
    Stale,
    #[error(transparent)]                 // forward Display + source, add nothing
    Io(#[from] std::io::Error),           // generates From, which `?` calls
}

root.canonicalize().with_context(|| format!("cannot access scan root {}", root.display()))?;

Batch write, one statement, one transaction

let tx = self.conn.transaction()?;
{
    let mut stmt = tx.prepare("INSERT OR IGNORE INTO files (…) VALUES (?1, …)")?;
    for file in files { stmt.execute(params![…])?; }
}                       // inner scope: stmt must be dropped before commit moves tx
tx.commit()?;

Gotchas worth remembering

  • du will not shrink. It reports logical size. Watch the volume's free space instead — and expect estimates, not exact numbers.
  • Clones are not backups. All copies share physical blocks on one volume; lose the blocks, lose them all.
  • A reclaimed file has a new inode. Sync services (iCloud, Dropbox) will see it as changed and may re-upload it.
  • Cloning is same-volume only (EXDEV), and APFS only — HFS+ and network mounts are refused.
  • clonefile refuses an existing destination (EEXIST). That is a feature: the engine never clones onto a live file.
  • A fresh clone wears the source's metadata — including the source's Finder tags and resource fork. Restoring the target's is mandatory, and so is deleting the strays.
  • Hashes never authorise a replacement. They nominate; the byte comparison inside the transaction decides.
  • Do not hand-delete .filecleaner.* files. Recovery uses them, and it will clean them up on the next run.

Building and testing

cargo build --release        # -> target/release/filecleaner
cargo test                   # unit + integration (integration needs macOS/APFS)
cargo clippy --all-targets

tests/scan_integration.rs    # walk + index, end to end
tests/funnel_integration.rs  # duplicates, near-duplicates, hardlinks, forks, staleness
tests/apfs_integration.rs    # clonefile, EEXIST/ENOENT, metadata round trip
tests/txn_integration.rs     # happy path, dry-run purity, races, recovery at each state
tests/fault_injection.rs     # scripted ApfsAdapter: EIO, ENOSPC, EPERM, mid-txn mutation

Integration test files open with #![cfg(target_os = "macos")], so the suite still compiles and the platform-neutral half still runs elsewhere.
