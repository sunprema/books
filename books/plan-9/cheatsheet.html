The 9P message set

Every message on the wire opens with size[4] type[1] tag[2], then type-specific fields; multi-byte integers are little-endian, strings are a 2-byte count plus UTF-8 bytes, no NUL anywhere. Tag NOTAG — (ushort)~0 — is reserved for the very first Tversion. Every T draws either the matching R (type = request+1) or the universal Rerror, except Tflush, which can never be answered Rerror.

Tauth/Rauthafid uname[s] aname[s]aqidOptional; a no-auth server answers Rerror and the client sends afid=NOFID to attach
Tattach/Rattachfid afid uname[s] aname[s]qidBinds fid to the root of the served tree; error if fid already in use
Twalk/Rwalkfid newfid nwname nwname×wname[s]nwqid nwqid×qid≤16 elements/msg (MAXWELEM); 0 elements clones fid onto newfid

Dialects negotiate in Tversion's version string: 9P2000.u adds n_uname/numeric errno/an extension stat field for Unix semantics; 9P2000.L instead adds a parallel Linux-VFS message set (Tlopen, Tgetattr, Tsymlink, Tlock, …) with numeric-only Rlerror. A server that doesn't recognize a dialect string may answer plain "9P2000".

bind / mount flags

Both calls take a flag governing how the new thing joins whatever is already at old; MCREATE/MCACHE OR onto a position flag, they don't replace it.

FlagValueEffectCLI
MREPL0x0000Default — replace old outright(none)
MBEFORE0x0001Splice onto the front of the union at old — searched first-b
MAFTER0x0002Splice onto the back of the union at old — searched last-a
MCREATE0x0004OR onto REPL/BEFORE/AFTER: this component accepts newly-created files-c
MCACHE0x0010mount only — cache file contents locally, re-verified on each open-C (mount only)
 
int bind(char *name, char *old, int flag);
int mount(int fd, int afd, char *old, int flag, char *aname);
int unmount(char *name, char *old);   // name="" undoes EVERYTHING at old

// /bin as a union: architecture binaries, then rc scripts, then mine first
bind -a /386/bin /bin
bind -a /rc/bin  /bin
bind -b -c $home/bin /bin   // -b -c: search ME first, creates land here

rfork flags

One bit vector covers everything from a plain fork() to a shared-memory thread; every resource defaults to shared, not copied.

FlagEffect
RFPROCCreate a child process. Without it, the flags modify the caller in place — no fork happens
RFFDGChild gets an independent copy of the fd table (same open channels, independent numbering)
RFCFDGChild starts with an empty fd table
RFNAMEGChild gets a private copy of the namespace — identical at the call, independent after
RFCNAMEGChild starts with an empty namespace, built up from nothing via mount
RFENVGChild gets an independent copy of /env
RFCENVGChild starts with an empty /env
RFMEMChild shares data+bss with the parent (stack is always copy-on-write regardless); legal only with RFPROC

fork() ≡ rfork(RFFDG|RFREND|RFPROC) — shares namespace and /env, copies the fd table. RFNAMEG/RFCNAMEG are mutually exclusive. RFNOMNT forbids further mounts and #-device dereference inside the new namespace — the primitive ch. 8's confinement is built from.

Plumbing

A message is six header lines, then a free-format data section with no header field of its own.

FieldMeaning
srcsending application (optional)
dstdestination port (optional — empty lets the rules choose)
wdirworking directory, used to resolve relative filenames
typeMIME-like tag; only type=text is currently supported
attrblank-separated name=value pairs, quoted per rc(1)
ndatabyte length of the data section — must be exact
datafree-format payload; the only section that may embed newlines, and has none trailing

Rule sets are tried in file order; the first whose patterns all succeed fires, and the rest are skipped. No match, and no pre-existing dst port → the write to /mnt/plumb/send fails.

factotum & capabilities

No root, no setuid — one agent holds keys, and one kernel device changes a user id, exactly once.

FilePurpose
rpcworld-writable; each open is a private channel — the actual auth transaction happens here
ctlowner-only; write key/delkey to add/remove keys, read to list current ones (public attrs only)
protoread-only; the protocols this factotum supports
confirmowner-only; a GUI reads this to prompt yes/no for a confirm-tagged key
needkeyowner-only; a GUI reads this to learn a requested key is missing
logowner-only; a trace of operations, for debugging
  • Key — attribute=value UTF-8 text; !attr is secret (never printed, never leaves factotum, except proto=pass). Query: attribute=value (exact) or attribute? (must exist) — every term must match.
  • Capability string — old-user@new-user@random-key.
  • /dev/caphash — write-only; host owner opens it exactly once, at boot, to register SHA1-HMAC(old@new, key).
  • /dev/capuse — any process writes the full capability string; the kernel matches the hash and changes that process's uid. Single-use, ~1 minute expiry, never crosses machines.
  • amount(fd, mntpt, flags, aname) — fauth → afd; auth_proxy(afd, getkey, "proto=p9any role=client"); mount(fd, afd, …).
  • auth_chuid(AuthInfo *ai, ns) — writes ai->cap to capuse; the standard way a login service becomes the authenticated user.
