Building the First Sidekick

No new techniques in this chapter. That is the point. Everything Kohai needs, you already learned — this is the training montage where the separate drills become one motion.

Choosing the model

Pick before you build, because it changes the economics of every later decision. Here are the three you will actually choose between:

We use claude-opus-5 for Kohai. Release notes need judgment about what a reader cares about, which is precisely where the capable model earns its price. Note also that on Opus 5 and Sonnet 5 the effort parameter defaults to high on the Claude API — you have to set it explicitly to use a different level, so if you want a cheaper, quicker run you must ask for one.

These numbers expire

Prices, IDs, context windows and cutoffs move. The figures above were current when this book was written, and Sonnet 5 additionally carried introductory pricing of $2/$10 per MTok through 31 August 2026. Do not hardcode any of it in a system you will still be running next year — chapter 8 shows how to ask the API instead.

Step one: the tools, for real

Chapter 3 gave you the schemas. Here are the implementations. Note the argument-list form of subprocess.run — no shell, so a ref name cannot become a command — and the cwd pin, so the agent cannot wander into another repository.

import subprocess

REPO = "/path/to/your/repo"

def git(*args) -> str:
    result = subprocess.run(
        ["git", *args],
        cwd=REPO, capture_output=True, text=True, timeout=20,
    )
    if result.returncode != 0:
        raise ToolError(result.stderr.strip() or "git failed")
    return result.stdout

def list_commits(since: str, until: str = "HEAD") -> str:
    return git("log", "--no-merges", "--pretty=%h%x09%an%x09%ad%x09%s",
               "--date=short", f"{since}..{until}")

def show_commit(sha: str) -> str:
    return git("show", "--stat", "--pretty=%B", sha)

HANDLERS = {"list_commits": list_commits, "show_commit": show_commit}

Step two: the dispatcher that cannot crash the run

Chapter 3's lesson, made concrete. Every failure becomes a tool result the model can read, and the message says both what went wrong and what would have worked:

class ToolError(Exception): ...

def run_tool(name: str, args: dict) -> tuple[str, bool]:
    """Returns (content, is_error). Never raises."""
    handler = HANDLERS.get(name)
    if handler is None:
        return f"Error: no tool named {name!r}. Available: {sorted(HANDLERS)}", True
    try:
        return handler(**args), False
    except ToolError as e:
        tags = git("tag", "--sort=-creatordate").split()[:5]
        return f"Error: {e} Recent tags: {tags}", True
    except TypeError as e:
        return f"Error: bad arguments for {name}: {e}", True

Step three: the loop

Unchanged from chapter 2, plus an iteration bound. Never ship an unbounded while around a paid API call:

import anthropic

client = anthropic.Anthropic()   # credentials come from the environment

SYSTEM = """You draft release notes for a software project.
Use the tools to read the actual commit history — never guess a commit.
Group changes by what a reader cares about (features, fixes, breaking
changes) and drop pure chores unless they change behaviour.
Cite the short hash for every entry."""

def draft_release_notes(since: str, max_iterations: int = 12) -> str:
    messages = [{"role": "user",
                 "content": f"Draft the release notes for everything since {since}."}]

    for _ in range(max_iterations):
        response = client.messages.create(
            model="claude-opus-5",
            max_tokens=16000,
            system=SYSTEM,
            tools=KOHAI_TOOLS,
            messages=messages,
        )

        if response.stop_reason != "tool_use":
            return finish(response)

        messages.append({"role": "assistant", "content": response.content})

        results = []
        for block in response.content:
            if block.type != "tool_use":
                continue
            content, is_error = run_tool(block.name, block.input)
            results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": content,
                "is_error": is_error,
            })

        # All results from one turn go back in ONE user message.
        messages.append({"role": "user", "content": results})

    raise RuntimeError("iteration limit reached without a final answer")

And a finish that does not pretend every non-tool_use ending is a success — chapter 8 expands this, but even the first version should not lie to you:

def finish(response) -> str:
    if response.stop_reason == "max_tokens":
        raise RuntimeError("truncated: raise max_tokens or narrow the range")
    if response.stop_reason == "refusal":
        raise RuntimeError("the model declined this request")
    return "".join(b.text for b in response.content if b.type == "text")

What the fight actually looks like

The shortcut you have now earned

Having written the loop by hand, you are allowed to stop writing it. The SDKs provide a Tool Runner that executes your tools and sends the results back automatically, so the round trip does not have to be written by hand:

runner = client.beta.messages.tool_runner(
    model="claude-opus-5",
    max_tokens=16000,
    tools=[list_commits_tool, show_commit_tool],
    messages=messages,
)
final_message = runner.until_done()

Use it. But you will debug it far better for having built the manual version first, because when a run goes strange you will know exactly which of the five steps is misbehaving rather than staring at a helper you never opened.

Adding memory to a working agent

Kohai works. Now make it remember. This is a three-line change plus a handler:

KOHAI_TOOLS = [
    list_commits_tool,
    show_commit_tool,
    {"type": "memory_20250818", "name": "memory"},   # new
]
HANDLERS["memory"] = memory_handler   # six commands, safe_path on every one

On the next run, Kohai views /memories before doing anything else — the protocol instruction the API adds for you — finds the note it wrote about your chore(deps): convention, and skips those commits without being told again. That is the whole memory arc, cashed in.

What you can do now that you couldn't before

You have built an agent. Not read about one — built one, with real tools over real data, a dispatcher that recovers instead of crashing, an iteration bound, honest handling of the ways a turn can end, and memory that survives the process.

And here is the honest power-level check: what you have is a good single agent. It is not yet reliable enough to run unattended, and it is one agent. The next two chapters address exactly those two gaps — in that order, because reliability is the harder one and most people skip it to build the fun one.
