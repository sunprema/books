Reference · Cheatsheet & Appendices

Cheatsheet

The thirty-second version of the whole book, then the appendices: configuration references, formulas, checklists, templates, and a glossary. Printable, and meant to be argued with in a design review.

The book in seven lines

  • Disconnection is a mode, not an error. Buffer at the edge, always.
  • Classify traffic; give each class its own targets and its own priority.
  • The partition key is an ordering decision before it is a distribution one.
  • At-least-once delivery + idempotent effects keyed on event id = effectively once.
  • Measure freshness, not availability. Label every stale answer.
  • Plans are versioned proposals; validate before publishing, damp before replanning.
  • State the safety boundary, and design so switching the platform off is safe.

Appendix A — Capacity-planning formulas

Four load cases
# steady state
ingest_eps   = N_devices × msgs_per_device_per_sec
ingest_bps   = ingest_eps × avg_bytes_per_msg

# peak
peak_eps     = ingest_eps × peak_factor

# reconnect — usually the sizing case
burst_eps    = (N_offline × buffered_msgs) / drain_window_sec

# storage
retained_B   = ingest_bps × replication_factor × retention_sec

# edge buffer sizing
disk_B       = msgs_per_sec × bytes_per_msg × max_outage_sec × (1 / compression)

# partitions
partitions   = ceil(burst_eps / per_partition_consumer_eps) × growth_headroom

Appendix D — Distributed-systems patterns

Outbox
Event row + business row in one local transaction; a relay forwards. Solves the dual write.
Inbox
Consumer records processed event ids and applies the effect in the same transaction. Bound the retention.
Idempotency key
Stable identity carried end to end, so any effect can be made repeat-safe.
Saga
Long-running work as a sequence of local transactions with compensations.
Retry with full jitter
Uniform over [0, backoff], not backoff ± noise. Spreads a fleet.
Retry budget
Cap on the fraction of traffic that may be retries.
Circuit breaker
Stop calling a failing dependency; let it recover.
Bulkhead
Separate resource pools so one slow dependency cannot exhaust all threads.
Store-and-forward
Durable local queue; release only on durable ack.
Dead letter + retry ladder
Bounded retries, then quarantine, so one bad message cannot block a partition.
Fencing
Revoke the old primary's authority before promoting a new one. Epoch numbers make it enforceable.

Appendix E — Edge-device security checklist

  • Per-device credentials; never a shared fleet secret.
  • Private keys in a secure element, non-exportable.
  • Mutual TLS; the device validates the server too.
  • Certificate rotation built and exercised before first expiry, with an overlap window.
  • Secure boot with signature verification at every stage.
  • A/B firmware slots with a commit window and automatic rollback.
  • Canary cohort chosen for diversity, then a soak period, then widening cohorts.
  • Commands signed individually, scoped, expiring, idempotent by id.
  • Command blast radius bounded: explicit cohort, rate limit, second approver above a threshold.
  • Revocation that works while the device is still installed.
  • Running fw and cfg versions reported in every envelope.
  • No safety-critical behaviour reachable from the control plane.

Appendix G — Architecture-review template

  1. What are the non-goals? (If none, the scope is not agreed.)
  2. What is the safety boundary, and is switching this off a safe action?
  3. Per traffic class: freshness, loss tolerance, retention, RPO, RTO.
  4. Four load cases, arithmetic shown, including the reconnect burst.
  5. Partition key and count, with the ordering requirement they serve.
  6. Where are effects idempotent, and under which identity?
  7. What does the field do with no cloud for six hours?
  8. Four failure modes, each with degraded behaviour and detection signal.
  9. Which dependencies are synchronous, and does any invert the hierarchy?
  10. What is measured, what pages, and against which SLO?
  11. Cost per asset per month, and the line that dominates it.
  12. When was failover last exercised — and failback?

Appendix I — Glossary

Allowed lateness
Extra time a window's state is retained past the watermark so late events can correct an emitted result.
Backpressure
A downstream slowdown signal propagated upstream — here, all the way to the device.
Bronze / Silver / Gold
Lakehouse layers: raw immutable, conformed, business-ready.
Commit window
Interval in which new firmware must report health or the bootloader reverts.
Compaction
Retention that keeps the latest value per key, so state can be rebuilt from the log.
Consist
The set of vehicles making up one train.
Device shadow
Cloud-side desired/reported state, usable while the device is offline.
Drain window
Time allowed to absorb a fleet's buffered backlog. A design choice, not a constant.
Drift
Production input distribution moving away from training reference — degradation without a fault.
Error budget
1 − SLO: the unreliability a target authorises you to spend.
Fencing
Revoking a failed primary's authority before promoting its replacement.
Freshness
Age of the newest data a consumer has processed. Usually the SLI that matters here.
Hot / warm / cold path
Three latency-versus-completeness budgets over the same events.
Linear referencing
Locating by measure along a route (milepost) rather than by coordinates.
Milepost
The rail network's primary linear referent. Not uniformly spaced; versioned by survey.
Poison pill
A message that cannot be processed and blocks its partition if retried forever.
QoS class
Application priority band deciding what is sent, batched, or evicted first.
Reconnect storm
Synchronised return of a fleet after an outage. The real sizing case.
RPO / RTO
Maximum tolerated data loss / recovery-time target.
Store-and-forward
Persist locally, transmit later, release only on durable acknowledgement.
Watermark
Event-time progress marker letting a processor decide a window is complete.
Write-ahead log
Durable append-only record written before an event is acknowledged anywhere.
If you remember one thing: the field must remain useful when the cloud is not. Everything else is an implementation detail of that promise.
