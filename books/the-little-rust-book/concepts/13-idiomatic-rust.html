Chapter twelve

Tidbits and Idiomatic Rust

You can now write Rust that compiles. This chapter is about writing Rust that another Rust programmer would recognise as Rust: the standard library you should know by heart, the macros you'll type daily, and the handful of habits that separate idiomatic code from translated code.

The standard library must-knows

Option<T> · Result<T, E>
Absence and failure. Learn map, and_then, unwrap_or, unwrap_or_else, ok_or, ok() — most match blocks on these are one combinator in disguise.
Vec<T> · String / &str
The two you touch every day. &str in signatures, String when you keep it. Same for &[T] versus Vec<T>.
HashMap · BTreeMap · HashSet
Hash for speed and no order, BTree when you want it sorted.
std::path::Path / PathBuf
The &str/String split again, for paths. Never build a path with string concatenation; use .join().
std::fs · std::io
fs::read_to_string for small files; BufReader::new(f).lines() for large ones. Unbuffered IO in a loop is the performance bug people find first.

Macros you'll actually type

dbg!(x)prints file, line and value — and returns it

todo!() deserves a mention of its own. It has type ! — "never returns" — which coerces to anything, so you can stub out a branch and keep compiling while you think. It is the type-driven way to work top-down.

Six habits

1. Return Result, don't panic — in libraries. unwrap() in a library is a decision that someone else's program should die. In a binary's main, or a test, or an example, it is fine. expect("…") is strictly better than unwrap() anywhere it survives review, because the message is where you explain why it can't happen.

2. Derive generously. #[derive(Debug)] on everything; Clone, PartialEq, Default where they make sense. It costs one line and makes your type usable in tests, logs and collections.

3. Take the narrowest parameter that works. &str over &String, &[T] over &Vec<T>, impl IntoIterator over a concrete collection. Your callers get more freedom and you get fewer allocations.

4. Make illegal states unrepresentable. Rust's enums are good enough that a struct with three optional fields and a comment explaining which combinations are valid should usually be an enum with three variants. The comment becomes a compile error.

5. Match instead of chaining if. Not for style — for exhaustiveness. A match that has to change when an enum grows is a feature.

6. Follow the naming conventions. Types UpperCamelCase, functions and variables snake_case, constants SCREAMING_SNAKE_CASE, modules snake_case. And the conversion prefixes carry real meaning: as_ is a free borrow, to_ is expensive, into_ consumes. Naming a cheap method to_ misleads a reader who knows the convention.

Most "fighting the borrow checker" is a design smell wearing a compiler error as a costume.

Debugging and the tool loop

cargo fmt                              # canonical formatting, no debate
cargo clippy --all-targets             # the lints beyond rustc's
cargo clippy --fix                     # apply the mechanical ones
RUST_BACKTRACE=1 cargo test            # a backtrace on panic
RUST_BACKTRACE=full cargo run          # …including runtime frames
cargo build --release                  # the only build worth timing

Clippy is not a style nag; a good share of its lints are correctness or performance. Run it before you push, and in CI with -D warnings so the build fails on new ones. Keep that flag out of your local loop, though — being blocked by a #[allow]-able lint mid-thought is how people learn to resent the tool.

A note on unsafe

unsafe does not turn off the borrow checker. It unlocks five specific abilities — dereferencing a raw pointer, calling an unsafe function, implementing an unsafe trait, mutating a static, and accessing a union field — and it means you now guarantee what the compiler no longer can. In edition 2024 the unsafe_op_in_unsafe_fn lint warns by default: an unsafe fn no longer silently grants its own body an unsafe block, so each operation is marked where it happens. Almost no application code needs any of this.

Before you continue

Run cargo fmt and cargo clippy --all-targets on everything you've written so far, and fix the warnings — read each one before you apply the fix, since clippy's explanations are a small idiom course in themselves. Then find one place you used unwrap() and replace it with a real Result.
