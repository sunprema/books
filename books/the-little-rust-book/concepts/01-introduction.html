Introduction

Why Rust, and how to read this

You already know how to program. What you want to know is what Rust asks of you that your other languages didn't, and whether the trade is worth it. That's what this chapter is for; the rest of the book is the trade, paid in installments.

Safety, speed, and no collector

Most languages pick two of three. C and C++ give you speed and control and hand you the memory bugs to go with them. Go, Java, C# and Python give you safety and productivity and a garbage collector that decides, at times not of your choosing, to stop the world for a moment. Rust's claim is that you can have memory safety and the machine, and pay for it at compile time instead of at run time.

The mechanism is ownership: a set of rules about who is responsible for a value and how long it lives, enforced by the compiler before your program ever runs. Every value has one owner; there is only one owner at a time; when the owner goes out of scope, the value is dropped. Three sentences. Chapter 4 is where they become real, and where you will argue with them for an afternoon.

The consequence worth stating plainly: there is no tracing garbage collector in a Rust program. Memory is freed at a point in the source you can put your finger on. That is why Rust turns up in kernels, browser engines, databases and embedded firmware — places where "the pause will come when it comes" isn't an acceptable answer.

The borrow checker is not a hazing ritual. It is the review comment you would have gotten three weeks later, delivered now.

The honest cost

Rust is harder to start than most of its competitors, and the difficulty is front-loaded. You will write code that is obviously correct and watch it fail to compile. That experience is the language teaching you an invariant you were relying on by accident. It passes. What replaces it is an unusual amount of confidence in code you have not run yet.

Versions this book assumes

Rust ships a stable release every six weeks; at the time of writing the current stable is 1.97.1 (16 July 2026). Everything here targets edition 2024, stabilised in Rust 1.85 and the default for a new project. If your toolchain is older than 1.85, run rustup update before chapter 1.

A word about editions

Rust versions its language rules separately from its compiler. An edition — 2015, 2018, 2021, 2024 — is a set of defaults and reserved keywords declared in one line of Cargo.toml. Crates on different editions link together in one build, which is how Rust changes defaults without splitting the ecosystem. You will see edition = "2024" in every manifest in this book and can otherwise forget editions exist.

What this book is, and isn't

This is a small, opinionated tour: thirteen short chapters that get you to the point of writing real programs, plus a cheatsheet. It is modelled on The Little Go Book — essentials and idioms, not coverage.

It is not a reference. It skips macros beyond using them, most of unsafe, the trait-system corners, and the async ecosystem past its first mile. When you want depth, the official book at doc.rust-lang.org/book is genuinely excellent and free; the Conclusion says where to go for what.

How to read it

In order, with a terminal open. Type the examples rather than reading them — the compiler's error messages are half the curriculum, and you only get them by making the mistakes. Each chapter ends with a Before You Continue: a small thing to build, usually ten minutes. Do it. The chapters are short because the typing is where the learning is.

Before you continue

Nothing to build yet — but decide now that you will type the examples instead of skimming them. The next chapter installs the toolchain, and from there every chapter has something to run.
