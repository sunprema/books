Chapter five

Structs, Enums, and Methods

Rust has no classes and no inheritance. It has structs for "this and that", enums for "this or that", and impl blocks to hang behaviour on either. That turns out to be enough, and the enums are better than you expect.

Three kinds of struct

// named fields — the usual one
struct Entity { name: String, hp: u32, alive: bool }

// tuple struct — fields by position; good for newtypes
struct Meters(f64);

// unit struct — no data; a marker, or a place to hang impls
struct Logger;

Meters(f64) is the newtype pattern, and it is used constantly. Wrapping a f64 costs nothing at run time and makes fn descend(d: Meters) impossible to call with a count of seconds.

Building and updating

let mut hero = Entity {
    name: String::from("Ada"),
    hp: 100,
    alive: true,
};
hero.hp -= 10;

// field init shorthand, when the variable is already named right
let name = String::from("Grace");
let other = Entity { name, hp: 100, alive: true };

// struct update syntax: take the rest from another value
let clone_ish = Entity { hp: 50, ..other };

Update syntax moves

..other takes the remaining fields by value. Here other.name is a String, so it moves and other is no longer usable as a whole. If you wanted a copy, derive Clone and write other.clone().

Methods and associated functions

impl Entity {
    // associated function — no self. Called Entity::new(…)
    fn new(name: &str) -> Self {
        Self { name: name.to_string(), hp: 100, alive: true }
    }

    // &self — reads
    fn is_hurt(&self) -> bool { self.hp < 100 }

    // &mut self — mutates
    fn damage(&mut self, amount: u32) {
        self.hp = self.hp.saturating_sub(amount);
        self.alive = self.hp > 0;
    }

    // self — consumes; the builder / conversion shape
    fn into_name(self) -> String { self.name }
}

The three receivers are the ownership rules again, in miniature. &self borrows, &mut self borrows exclusively, self takes ownership and is the last thing that can happen to the value. Rust has no constructors as a language feature; new is a convention, and any associated function returning Self will do.

saturating_sub above is not decoration. hp is a u32; plain subtraction below zero panics in debug and wraps to four billion in release. Saturating at zero is what we actually meant.

Enums that carry data

This is where Rust's enums stop resembling C's. Each variant may carry its own data, in any of the three struct shapes: 

enum Shape {
    Point,                       // unit
    Circle(f64),                 // tuple
    Rect { w: f64, h: f64 },      // named fields
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Point => 0.0,
            Shape::Circle(r) => std::f64::consts::PI * r * r,
            Shape::Rect { w, h } => w * h,
        }
    }
}

A Shape is exactly one of those, and the match destructures it in the same breath as choosing the branch. There is no instanceof, no downcast, and no way to read Circle's radius out of a Rect.

Option and Result are just enums

enum Option<T> { None, Some(T) }
enum Result<T, E> { Ok(T), Err(E) }

That is the whole definition. There is no null in Rust; there is a two-variant enum in the standard library, and the compiler will not let you reach the Some value without saying what happens for None. The billion-dollar mistake is fixed by a library type and an exhaustive match.

Derive macros

Most of the traits you want are mechanical. Ask for them: 

#[derive(Debug, Clone, PartialEq)]
struct Entity { name: String, hp: u32, alive: bool }

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Default)]
struct Point { x: i32, y: i32 }
Debug
Enables {:?}. Put it on everything.
Clone / Copy
Clone is an explicit .clone(); Copy makes assignment copy instead of move. Copy requires every field to be Copy, so a struct holding a String cannot have it.
PartialEq / Eq
==. Eq additionally promises reflexivity, which floats can't give you.
PartialOrd / Ord
Comparison and sorting.
Hash
Required to be a HashMap key.
Default
Gives Type::default() and the ..Default::default() idiom.

Before you continue

Model a small domain — a game entity, or a config file — with one struct and one data-carrying enum. Add an associated new, one &self method and one &mut self method. Derive Debug and print it with {:#?}. Then try deriving Copy on the struct with the String in it and read what the compiler says.
