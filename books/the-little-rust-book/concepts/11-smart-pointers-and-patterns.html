Chapter ten

Smart Pointers and Common Patterns

"One owner" is a good rule that occasionally isn't enough — a tree of unknown depth, a value two parts of the program share, a graph. The standard library has a small set of types that bend the rule in a controlled way, and each is honest about what it costs.

Box<T>: one owner, on the heap

Box is the simplest smart pointer: a single owning pointer to a heap allocation. It has no runtime overhead beyond the allocation, and dropping it frees the value. Its most common job is giving a recursive type a finite size. 

#[derive(Debug)]
enum Tree {
    Leaf(i32),
    Node(Box<Tree>, Box<Tree>),
}

let t = Tree::Node(
    Box::new(Tree::Leaf(1)),
    Box::new(Tree::Node(
        Box::new(Tree::Leaf(2)),
        Box::new(Tree::Leaf(3)),
    )),
);

Without the boxes, Tree would contain a Tree would contain a Tree: the compiler cannot compute its size and says so. A Box is pointer-sized whatever it points at, which cuts the recursion. The other everyday use is Box<dyn Trait> from chapter 8.

Rc and Arc: many owners

use std::rc::Rc;

let config = Rc::new(load_config());
let a = Rc::clone(&config);      // count 2 — no data copied
let b = Rc::clone(&config);      // count 3
println!("{}", Rc::strong_count(&config));   // 3
// last one out frees it

Rc<T> is a reference count. The value lives until the last handle is dropped. Arc<T> is the same thing with an atomic counter, which is what makes it safe to share across threads — and what makes each clone a little more expensive. Single thread: Rc. Across threads: Arc. The compiler will stop you getting it wrong.

Write Rc::clone(&x), not x.clone()

Both compile and both bump the count, but the associated-function form makes the reader's job easy: cheap pointer clone here, potentially deep clone everywhere else in the file. This is a style convention with real teeth on a hot path.

One catch: Rc gives you shared immutable access. Two owners plus mutation is exactly what the borrow rules forbid, so if you want it you have to ask explicitly.

RefCell: the check moves to run time

use std::cell::RefCell;
use std::rc::Rc;

let shared = Rc::new(RefCell::new(Vec::new()));
let other = Rc::clone(&shared);

shared.borrow_mut().push(1);
assert_eq!(other.borrow().len(), 1);

RefCell<T> enforces the same one-mutable-or-many-shared rule, but at run time: borrow() and borrow_mut() hand out guards and panic if the rule is broken. You have not escaped the rule, you have moved when it is checked — and turned a compile error into a crash. Use it where the access pattern is genuinely dynamic, not to avoid thinking.

Cycles, and the one leak Rust allows

Rust prevents use-after-free and double-free. It does not promise you can't leak — and two Rcs pointing at each other are the standard way to do it, because neither count ever reaches zero. The fix is Weak<T>: a handle that does not own, and which you upgrade() to an Option<Rc<T>> when you want to use it. Parent pointers, observers and caches are the usual places.

Drop and RAII

struct Timer { label: &'static str, start: std::time::Instant }

impl Drop for Timer {
    fn drop(&mut self) {
        eprintln!("{}: {:?}", self.label, self.start.elapsed());
    }
}

{
    let _t = Timer { label: "parse", start: std::time::Instant::now() };
    parse_everything();
}   // prints here, on every path out — including a panic unwind

Drop runs deterministically at the closing brace. No finaliser queue, no "eventually". That is why Rust needs no try/finally, no defer, and no with statement: file handles close, locks release and buffers flush because their owner went out of scope. It is the same mechanism as chapter 4's rule 3, used on purpose.

Two patterns you'll write yourself

Newtype. A one-field tuple struct, free at run time, that makes a distinct type out of a common one. It buys you type safety (Meters is not Seconds), a place to put impls, and a way around the orphan rule.

Builder. When a constructor would need eight arguments, six of them optional, return Self from each setter and take self by value so the calls chain: 

#[derive(Default)]
struct ServerBuilder { port: Option<u16>, tls: bool }

impl ServerBuilder {
    fn port(mut self, p: u16) -> Self { self.port = Some(p); self }
    fn tls(mut self, on: bool) -> Self { self.tls = on; self }
    fn build(self) -> Result<Server, ConfigError> { /* … */ }
}

let server = ServerBuilder::default().port(8080).tls(true).build()?;

Before you continue

Implement a small binary tree with Box and write a recursive sum(). Then build a tiny graph where two nodes share a child using Rc, print Rc::strong_count at a couple of points, and try adding a parent pointer with Rc — then convince yourself it leaks, and change it to Weak.
