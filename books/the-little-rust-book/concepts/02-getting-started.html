Chapter one

Getting Started

Rust's tooling is one of the genuinely good reasons to use it, and it all arrives in a single install. Fifteen minutes here buys you a compiler, a build system, a package manager, a formatter, a linter and a language server that agree with each other.

rustup: one installer, every toolchain

Don't install Rust from your distribution's package manager. Install rustup, the official toolchain manager. It puts rustc (the compiler), cargo (build + package manager), clippy (linter) and rustfmt (formatter) on your path, and it can hold several toolchains side by side so a project pinned to an older Rust doesn't fight your default.

macOS / Linux / WSL

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

On Windows, download rustup-init.exe from rustup.rs; it will offer to install the Microsoft C++ build tools, which Rust needs for linking. Then, in a new shell: 

rustc --version   # rustc 1.97.1 (…)
cargo --version
rustup update     # later: pulls the newest stable

The components you want

clippy and rustfmt normally come with a stable toolchain already. If a command is missing: rustup component add clippy rustfmt. The language server is rustup component add rust-analyzer, though most editor extensions download and manage the matching binary themselves, so you rarely run that by hand.

Your first project

Rust programs are built by Cargo, not by invoking rustc directly. You will call rustc roughly never. 

cargo new hello
cd hello

That gives you a package: a manifest, a source directory, and a fresh git repository.

Cargo.toml

[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]

edition = "2024" is the default that cargo new writes today. You can ask for another with cargo new --edition 2021 …, and you almost never should.

Hello, world!

src/main.rs

fn main() {
    println!("Hello, world!");
}

main is the entry point. println! is a macro, not a function — that's what the exclamation mark means. For now, read it as "print with formatting"; chapter 2 uses it properly. 

cargo run
#    Compiling hello v0.1.0 (/path/to/hello)
#     Finished `dev` profile [unoptimized + debuginfo] in 0.31s
#      Running `target/debug/hello`
# Hello, world!

The four commands

What you will actually type
CommandDoesWhen
cargo checkType-checks, produces no binaryThe fast inner loop
cargo runBuilds and runs (debug)Trying it out
cargo testBuilds and runs the testsBefore you push
cargo build --releaseOptimised binary in target/release/Shipping, benchmarking

cargo check deserves the emphasis. It runs the whole front end — parsing, type checking, borrow checking — and skips code generation, which is most of the time. When you are arguing with the borrow checker, that is the loop you want.

Editor setup

One name matters: rust-analyzer. It is the language server behind inline errors, completion, go-to-definition, type hints on every let, and one-keystroke "apply the compiler's suggestion".

VS Code
Install the rust-lang.rust-analyzer extension. If you have the old rust-lang.rust extension, uninstall it — the two conflict.
JetBrains
RustRover, or the Rust plugin in IntelliJ IDEA. Both bundle their own analysis; no separate install needed.
Neovim / Helix / Emacs
Point your LSP client at the rust-analyzer binary.

If the editor says "failed to discover workspace"

rust-analyzer needs a Cargo.toml at the folder you opened and rustc on PATH. Opening a subdirectory of a project, or installing Rust without rustup, produces exactly that error.

Before you continue

Create and run a new Cargo project. Then change the greeting, run cargo check, and deliberately delete a semicolon so you can read your first Rust compiler error. Notice that it tells you where the fix goes.
