Chapter two

The Basics

This is the chapter where Rust looks like every other language you know, with two exceptions that matter later: bindings are immutable by default, and almost everything is an expression.

Bindings and mutability

let x = 5;
// x = 6;            // error[E0384]: cannot assign twice to immutable variable

let mut y = 5;
y += 1;               // fine

Immutable-by-default is not a style preference. It is the assumption the compiler leans on when it reasons about aliasing in chapter 4, and it means mut in a signature is real information: this thing changes.

Types are inferred, but you can always write them, and at function boundaries you must: 

let count: u32 = 0;
let ratio = 0.5;              // f64 by default
const MAX_RETRIES: u8 = 3;   // const: no `mut`, type required, inlined

Shadowing is not mutation

Re-using let on the same name creates a new binding that hides the old one — and it may have a different type. This is how Rust programmers do the "parse and replace" step without inventing input_str and input_num. 

let spaces = "   ";         // &str
let spaces = spaces.len();   // usize — same name, new binding

The distinction, once

mut changes the value in an existing slot and can never change its type. Shadowing makes a new slot and can. If you find yourself reaching for mut only to convert something, you wanted shadowing.

char is worth a second look: 'ß', '漢' and '🦀' are each one char. A char is not a byte, which is exactly why strings behave the way they do in chapter 6.

Integer overflow behaves differently per profile

In a debug build, overflowing an integer panics. In a release build it wraps. That is deliberate — you find the bug in development and don't pay a branch in production — but it means "it worked in debug" is not proof. When wrapping is what you want, say so: wrapping_add, checked_add (returns Option), saturating_add, overflowing_add.

Tuples and arrays

let tup: (i32, f64, char) = (500, 6.4, 'r');
let (a, b, c) = tup;      // destructuring
let first = tup.0;        // positional access

let arr = [1, 2, 3, 4, 5];   // [i32; 5] — length is part of the type
let zeros = [0u8; 32];         // 32 zero bytes
let n = arr[2];               // bounds-checked at run time

An array has a fixed length known at compile time and lives on the stack. When you want to grow, you want Vec<T> — chapter 6. Indexing out of bounds is a panic, not undefined behaviour; that check is the safety, and it is one comparison.

The empty tuple () is called unit. It is the type of an expression that produces no value — the return type of a function with no ->. You will see it in error messages constantly, so it is worth naming now.

Everything is an expression

A block's last expression, written without a semicolon, is the block's value. A semicolon discards it and yields (). This one rule explains a surprising amount of Rust's shape. 

let label = if n > 100 { "big" } else { "small" };

let squared = {
    let t = n * n;
    t + 1              // no semicolon — this is the block's value
};

fn double(x: i32) -> i32 {
    x * 2              // no `return` needed, and none written
}
A stray semicolon in Rust doesn't change punctuation. It changes the return type.

Printing and formatting

let name = "Ada";
let pt = (3, 4);

println!("hello, {name}");            // captured from scope
println!("hello, {}", name);          // positional
println!("{pt:?}");                   // Debug:  (3, 4)
println!("{pt:#?}");                  // pretty Debug, multi-line
println!("{:>8.2}", 3.14159);        // right-aligned, 2 dp:  "    3.14"

let s: String = format!("{name} at {pt:?}");   // returns, doesn't print
eprintln!("warning: {s}");            // stderr
{} — Display
For humans. A type opts in by implementing Display; that's why {} on your own struct won't compile yet.
{:?} — Debug
For programmers. You get it for free with #[derive(Debug)], and you should put that on nearly everything.

Before you continue

Write a small program using variables, tuples and arrays: build an array of five measurements, compute a (min, max) tuple with a loop, and print it both ways — {:?} and a formatted {} line with two decimal places. Then make one of the bindings immutable that shouldn't be, and read the error.
