Quick reference

The whole thing, one page

The language, the failure vocabulary and the CLI — for when you are writing a spec rather than learning one.

The thirty-second summary

A .aspec.py file is valid Python that is never executed. The model is the runtime. The file declares tasks (instruction + typed inputs and output), the tools each may use, the rules each must honor, how they wire together, and what happens when things fail. A CLI called aspec lints, plans, graphs, diffs, evals and runs the same file.

If it declares, it's allowed; if it computes, it's forbidden.

What may be at module level

  • a docstring — revision history and postmortems
  • imports from agentspec, pydantic, typing, other .aspec.py files
  • constants holding literals or rule lists
  • class definitions

Forbidden anywhere: functions, loops, I/O, arbitrary expressions.

Task skeleton

class DoThing(Task):
    """Required. This IS the instruction."""
    some_input: str          # bare annotation = input
    returns: ResultModel     # a named schema, never anonymous

    tools = [ ... ]
    constraints = [ ... ]
    undo = "how to reverse completed effects"
    on_uncertain = { ... }
    on_item_failure = "skip_and_report"
    on_failure = "abort"
    meta = {"version": "1.0.0"}

Reserved attributes

tools · constraints · undo · on_uncertain · on_failure · on_item_failure · meta. Anything else is an error — except in an orchestrator, where non-reserved assignments are the pipeline.

Schemas

  • Plain Pydantic BaseModels.
  • Enum[...] / Literal[...] = closed set.
  • Field(le=, ge=, max_length=) bounds are binding.
  • x | None = optional.
  • Never invent, coerce or pad values to fill the shape.

Rules

Rule("kebab-id", "the rule text",
     why="the cost of breaking it",
     severity="must",    # must (default) | should | may
     since="v1.1.0")
  • must is inviolable; should yields to a conflicting must.
  • On conflict, the more conservative action wins.
  • Parent constraints bind children; children may only add stricter.
  • Compose doctrine with DOCTRINE + [ ... ].
  • Lint warns on a must with no why.

Tools

Tool("gh", ops=["pr create"])
Tool("python3", scripts=["lib/validate.py"])
Tool("read", paths=["<root>/skills/**"])
Tool("git", ops=["add", "push"], exclusive=True)
Tool("house-plugin", ops=["build"], strict=True)
  • Missing mechanism → substitute: same ops, same rules, recorded.
  • strict=True → no substitute; unusable = task failure.
  • A refused operation is a boundary, not a missing mechanism.
  • The tool list must cover the whole procedure, degradations included.

Pipeline (inside an orchestrator)

events = Scan(limit=limit)                       # step
plans  = [Triage(data=it) for it in events.items]  # fan-out
paid   = [Pay(id=p.id) for p in plans
          if p.tier in ["a", "b"]]                   # filter
mark   = MarkDone() if events.found else None      # gate
report = Digest(all=paid)                        # join
  • Order is derived from references, not written.
  • Filters test literal membership/equality only.
  • A false gate is a clean skip, never an error.

Derivation — first match wins

route = {
    not scan.ok:    {"outcome": "scan_failed"},
    not scan.found: {"outcome": "no_updates"},
    True:           {"outcome": "pr_opened"},
}

Use it when a routing decision has more than one consumer. Copy its fields verbatim into the report; author only the prose.

Failure vocabulary

"abort"stop, run undos in reverse, report
{literal}return this default, continue
Retry(max=, backoff_s=, then=)N attempts, then then
Escalate(channel=, timeout_s=, then=)page a human, bounded wait
on_item_failureskip_and_report | abort
on_uncertainthe honest answer; never a failure

The whole environment

env.now · env.cwd · env.user · env.platform · env.run_id. Nothing else exists; anything else a task needs is an input.

The agent's contract

  1. Root task = the one nothing references (unless dispatch names one).
  2. Run in dependency order; honor gates, filters, fan-out.
  3. Stay inside declared tools; honor every rule.
  4. Apply failure semantics exactly; on abort, unwind in reverse.
  5. Never ask questions — only a declared Escalate.
  6. Finish on the contract: real values or a declared fallback.

Gotchas worth remembering

  • An outcome enum that cannot separate two endings is a label, not a key.
  • A degraded path usually needs a larger tool list, not a subset.
  • A must weakened to a should is a capability change — diff flags it.
  • An exclusive tool with no undo is lint AS034.
  • A success that required improvisation is an incident — the expensive kind.

The dev → production loop

  1. aspec run --dev — pauses at declared doubt points.
  2. Gap report: “N clarifications — each is a candidate rule.”
  3. Graduate each into a Rule with why + since.
  4. Re-run. Gap count → 0 = ready for unattended dispatch.
