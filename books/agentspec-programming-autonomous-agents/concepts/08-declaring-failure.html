Chapter eight

Declaring Failure

Every task states what to do when it is uncertain and what to do when it fails — including how to reverse what it already did. And the runtime applies those declarations exactly: the agent never improvises a recovery.

That word exactly is the design. A capable model asked to recover from a failure will invent a recovery, and the recovery will be plausible, and it will be different next Tuesday. AgentSpec takes the invention away and replaces it with a small vocabulary you choose from in advance.

The vocabulary

Failure semantics, §8
DeclarationBehavior
on_failure = "abort" Stop; unwind completed steps via their undo in reverse order (a saga); report.
on_failure = {…} Return that declared default; the routine continues.
Retry(max=N, backoff_s=S, then=…) N fresh attempts, then the then behavior.
Escalate(channel=…, timeout_s=T, then=…) Notify the channel, wait up to T for a human, then then.
on_item_failure Fan-out only: skip_and_report or abort.
on_uncertain = {…} The output when the task genuinely cannot decide. Never a failure.
undo = "…" How to reverse this task's completed effects.

Uncertainty is not failure

Start with on_uncertain, because it is the one with no equivalent in ordinary error handling. It declares what the task returns when it genuinely cannot decide — and choosing it is always legitimate, never a failure.

Here is SelectUpdate, the routine's one judgment call, saying what it does when the judgment will not come: 

on_uncertain = {
    "selected": False,
    "name": "",
    "target": "",
    "kind": "patch",
    "rationale": "could not choose safely; skipping tonight",
}

Skipping tonight is a perfectly good night's work. Without this declaration, the shape of the output would be pressing for a package name and a version, and the cheapest way to satisfy a required field is to produce a plausible one. Declaring the honest answer in advance is what keeps the pressure off.

The distinction to hold

on_uncertain is a decision the task is allowed to make. on_failure is the task not working. Collapsing them turns every hard call into an incident, and every incident into a shrug — depending on which way you collapse.

Retry: a lesson made mechanical

depbot's test run carries this: 

on_failure = Retry(
    max=2,
    backoff_s=30,
    then={
        "passed": False,
        "failures": 0,
        "log_excerpt": "test harness failed to run",
    },
)

Two attempts, thirty seconds apart, and if the harness still will not run, a declared literal that says so honestly — note failures: 0, because zero tests failed; the harness never got far enough to have an opinion.

This exact declaration comes from a real night. The module docstring records it: a flaky test failed a clean update; the branch was left behind and confused the next run. The retry is the first half of the fix. The second half is a whole extra step — CleanupBranch, gated on not tests.passed — so a failed run leaves no residue. A lesson that would elsewhere have become team folklore is here two lines of declaration and a gate.

Escalate: the human, declared in advance

Sometimes the right recovery is a person. AgentSpec allows that, but insists you name them before the incident rather than during it: 

on_failure = Escalate(channel="secondary-oncall", timeout_s=600,
                      then={"paged": False, "acknowledged": False})

A channel, a bounded wait, and a declared answer for when nobody comes. Every part of that is a decision better made calmly on a Tuesday afternoon than by a routine at 4 a.m. And note the constraint from chapter one that this construct exists to satisfy: a routine never asks questions — escalation happens only through a declared Escalate channel.

Abort, and the unwind

on_failure = "abort" is the strongest declaration, and it brings the saga with it: stop, then perform the undo declarations of already-completed steps in reverse completion order, then report.

undo is prose, not code — a sentence describing how to reverse the task's completed effects: 

undo = "Delete the depbot/* branch and restore the pristine lockfile"

The toolchain treats a missing undo as a real defect, not a style note. Lint flags AS034 when a task holds an exclusive tool and has no way to reverse its effects through abort — that is, when the routine can change something durable and the saga has no handle on it.

The one step that must always run

There is a failure mode no construct on this page catches, and depbot closes it with a rule:

notify-on-every-path must

Notify is the last action on every terminal path, including after an abort's unwind.

a bot that fails silently gets un-installed the hard way.

An abort that skips the notification has done the hardest part of the job — detecting the problem — and thrown the result away. The transcript of an unattended run is read by nobody. If the routine does not reach the operator, it did not happen.

So what did we actually gain?

Recovery behavior chosen while calm, written where a reviewer can argue with it, and applied identically every night — plus a declared way to reverse a half-finished run, which is what makes an abort safe enough to actually use.
