The plain words, next to the real Elixir words, in one place.

30-second summary

Workers own private memory and only talk by passing notes. Some workers (GenServer) hold state and answer notes; some (Supervisor / DynamicSupervisor) don't do work themselves — they just watch other workers and hire replacements the instant one stops. A Registry lets you find a worker by a name you chose, even after it's been replaced. Supervision restarts the worker, never the business data that only ever lived in its memory.

Two questions to ask before writing a worker

  • Does this need its own memory, its own lifecycle, or the ability to fail in isolation? If not, a plain function is enough.
  • If this crashes, can everything it was holding be rebuilt from somewhere durable — or does it need to live somewhere durable in the first place?

Where to go next (briefly)

This book deliberately stayed small. Once these ideas feel natural, the next things worth a look are: :gen_statem for more elaborate state machines, ETS for very fast in-memory lookup tables, releases and observability for running this in production, and — if one machine stops being enough — distributed Erlang for spreading a supervision tree across more than one node.
