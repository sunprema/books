Appendix — Quick reference

The Small Card for the Big Room

Real name: Cheatsheet — views, commands, runbooks, licence checklist

When the night is loud, you do not want a story. Here are the questions to ask the database, in the order you will need them. Examples are for Oracle Database 19c; in a pluggable setup, first check where you are with SHOW CON_NAME.

1. Instance and database status

AskCommand / view
Instance stateSELECT instance_name, status, database_status FROM v$instance;
Log mode, open modeSELECT name, log_mode, open_mode FROM v$database;
Where am I (CDB/PDB)?SHOW CON_NAME · SELECT con_id, name, open_mode FROM v$pdbs ORDER BY con_id;
Switch containerALTER SESSION SET CONTAINER = orderstest;
Startup stepsSTARTUP NOMOUNT; → ALTER DATABASE MOUNT; → ALTER DATABASE OPEN;
Open / keep a PDBALTER PLUGGABLE DATABASE x OPEN; · ALTER PLUGGABLE DATABASE x SAVE STATE;
Parameter, now vs savedv$parameter (running) · v$spparameter (SPFILE) · ALTER SYSTEM SET p=v SCOPE=BOTH;
Save config as textCREATE PFILE='/stage/init_backup.ora' FROM SPFILE;
Redo groups, filesv$log (group#, sequence#, status) · v$logfile
Current SCNSELECT CURRENT_SCN FROM v$database;
Listener, serviceslsnrctl status · lsnrctl services · v$services

2. Sessions and blocking

AskCommand / view
Who is connected?SELECT sid, serial#, username, machine, program, service_name, server FROM v$session WHERE type='USER';
Who is blocked, by whom?SELECT sid, serial#, blocking_session, final_blocking_session, event, sql_id, seconds_in_wait FROM v$session WHERE blocking_session IS NOT NULL;
What are active sessions waiting on?SELECT wait_class, COUNT(*) FROM v$session WHERE status='ACTIVE' AND type='USER' GROUP BY wait_class ORDER BY 2 DESC;
Top waits, last 15 minv$active_session_history grouped by event, sample_time > SYSDATE - 15/1440 (Diagnostics Pack)
Why ORA-01555?v$undostat: maxquerylen, ssolderrcnt, nospaceerrcnt, tuned_undoretention · SHOW PARAMETER undo
Undo extent statesSELECT status, SUM(bytes)/1024/1024 mb FROM dba_undo_extents GROUP BY status;

3. Storage and tablespaces

AskCommand / view
Tablespace % usedSELECT tablespace_name, ROUND(used_percent,1) FROM dba_tablespace_usage_metrics ORDER BY used_percent DESC; (size is in blocks)
Datafile growth limitsdba_data_files: bytes, autoextensible, maxbytes, increment_by
Who is using temp?v$tempseg_usage joined to v$session on saddr = session_addr
Undo tablespace, retentionSELECT tablespace_name, retention FROM dba_tablespaces WHERE contents='UNDO';
Reclaim in a tableALTER TABLE t ENABLE ROW MOVEMENT; then ALTER TABLE t SHRINK SPACE CASCADE;
Shrink tempALTER TABLESPACE temp SHRINK SPACE KEEP 2G;
Resize datafileALTER DATABASE DATAFILE '<path>' RESIZE 20G;

4. Backup and recovery

-- RMAN: set once
CONFIGURE RETENTION POLICY TO RECOVERY WINDOW OF 7 DAYS;
CONFIGURE CONTROLFILE AUTOBACKUP ON;
-- run: weekly, daily
BACKUP INCREMENTAL LEVEL 0 DATABASE TAG 'weekly0';
BACKUP INCREMENTAL LEVEL 1 DATABASE TAG 'daily1';
BACKUP ARCHIVELOG ALL NOT BACKED UP 1 TIMES;
-- prove it
CROSSCHECK BACKUP;   DELETE NOPROMPT OBSOLETE;
BACKUP VALIDATE CHECK LOGICAL DATABASE;
RESTORE DATABASE VALIDATE;
AskCommand / view
Did backups run?SELECT status, input_type, start_time FROM v$rman_backup_job_details ORDER BY start_time DESC;
Flashback on, restore pointALTER DATABASE FLASHBACK ON; · CREATE RESTORE POINT p GUARANTEE FLASHBACK DATABASE;
Rewind databasefrom MOUNT: FLASHBACK DATABASE TO RESTORE POINT p; then ALTER DATABASE OPEN RESETLOGS; · DROP RESTORE POINT p;
Rewind one tableALTER TABLE t ENABLE ROW MOVEMENT; FLASHBACK TABLE t TO TIMESTAMP SYSTIMESTAMP - INTERVAL '30' MINUTE;
PDB point-in-timeALTER PLUGGABLE DATABASE x CLOSE; SET UNTIL TIME ...; RESTORE / RECOVER PLUGGABLE DATABASE x; OPEN RESETLOGS; (from root, in a RUN block)
Data Guard lagSELECT name, value FROM v$dataguard_stats WHERE name IN ('transport lag','apply lag');
Broker movesVALIDATE DATABASE 'x'; SWITCHOVER TO 'x'; FAILOVER TO 'x'; REINSTATE DATABASE 'x'; (in DGMGRL)

5. Diagnostics

AskCommand / view
Alert log, last hourSELECT originating_timestamp, message_text FROM v$diag_alert_ext WHERE originating_timestamp > SYSTIMESTAMP - INTERVAL '1' HOUR;
ADRCIshow alert -tail 50 · show incident · ips create package incident <n> · ips generate package 1 in /tmp
Real plan with row countsSELECT /*+ gather_plan_statistics */ ...; then SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST'));
Costly SQLv$sql: executions, parse_calls, buffer_gets, elapsed_time
Fresh statisticsEXEC DBMS_STATS.GATHER_TABLE_STATS(USER,'ORDERS',cascade=>TRUE);
Trace one sessionEXEC DBMS_MONITOR.SESSION_TRACE_ENABLE(session_id=>:sid, serial_num=>:serial, waits=>TRUE, binds=>FALSE); … SESSION_TRACE_DISABLE(:sid,:serial); OS: tkprof <trc> out.txt sys=no sort=exeela
Scheduler job historydba_scheduler_job_run_details: job_name, status, error#, run_duration
Who has what?dba_sys_privs · dba_role_privs · dba_users WHERE oracle_maintained='N' · unified_audit_trail
Connection checkstnsping //host:1521/svc · sqlplus u@//host:1521/svc · ALTER SYSTEM REGISTER; · SHOW PARAMETER local_listener

Runbook skeletons

Each is a spine: fill in names, paths and owners for your shop. The order matters more than the words.

Backup verification

  1. Latest job succeeded? (v$rman_backup_job_details)
  2. CROSSCHECK BACKUP; and read what is expired.
  3. BACKUP VALIDATE CHECK LOGICAL DATABASE;
  4. RESTORE DATABASE VALIDATE;
  5. Control file and SPFILE are in the set (autobackup on).
  6. Real restore test somewhere else, on a schedule; write the time it took.

Recovery

  1. Name what is lost: instance, datafile, control file, data (bad change), PDB, site.
  2. Stop further harm: pause the app, keep logs and the alert log.
  3. Pick the path that keeps the most good data: crash recovery · datafile restore · Flashback · point-in-time (SET UNTIL) · recover elsewhere.
  4. Run it; OPEN RESETLOGS only when the path needs it.
  5. Validate: counts, newest order, app smoke test. Take a fresh backup.
  6. Write the timeline and what you decided at each fork.

Space exhaustion

  1. Which layer is full: filesystem, tablespace, temp, undo, archived redo area?
  2. dba_tablespace_usage_metrics; dba_data_files for autoextend caps.
  3. Temp? Find sessions in v$tempseg_usage and their sql_id.
  4. Buy time safely (add or resize a datafile); then fix the cause.
  5. Reclaim only with a plan (SHRINK SPACE, temp shrink).
  6. Add an alert threshold so the next one is early.

Connection failures

  1. Client: right name, right service, right tnsnames.ora?
  2. Network: tnsping from the app host, not from the server.
  3. Listener: lsnrctl status / services; is the service listed?
  4. Not registered? Check local_listener, then ALTER SYSTEM REGISTER;
  5. Service and PDB: v$services; PDB open?
  6. Authentication: account locked or expired (dba_users)? Database full of sessions?

Performance incident

  1. Write the symptom and the start time. Change nothing yet.
  2. Waits by class; top events; blockers.
  3. Alert log for the same window.
  4. Top SQL; actual plan with ALLSTATS LAST; are statistics sane?
  5. One change, measured against the baseline; keep a way back.
  6. Package evidence (ips) if Oracle Support is needed.

Patching and upgrades

  1. Read the patch readme; record current patch level and home.
  2. Rehearse on a clone first; time it.
  3. Fresh, validated backup; guaranteed restore point if you use Flashback.
  4. Run prechecks (AutoUpgrade analyze mode); fix findings.
  5. Apply; check logs; validate data, config, application.
  6. Rollback plan with a go/no-go time; communicate cutover.

Disaster recovery

  1. Confirm the main site is really lost, not just unreachable.
  2. Check both lags; VALIDATE DATABASE for a planned move.
  3. Planned: SWITCHOVER. Unplanned: FAILOVER, accepting what was not shipped.
  4. Point apps at the role-based service; confirm no lost or doubled orders.
  5. REINSTATE the old main when it returns (needs Flashback Database on).
  6. Rebuild protection; rerun the drill soon.
