How Long a Borrowed Thing Is Allowed to Stick Around

Rust calls this: lifetimes

Last chapter, we saw the strict friend refuse to hand back a look at a truck that had already been thrown away — and it left a small note about something called a "lifetime" that we hadn't met yet. Time to meet it properly. It sounds bigger and scarier than it is.

Here's the problem

Say Sam and Ann each show up with their own truck, and you want to write a little helper that looks at both and hands back a look at whichever one is bigger, so whoever asked can go measure it further.

You reach for the same move as last chapter — just borrow both, don't take either one:

rust — this one, the strict friend won't accept

fn bigger_truck(x: &String, y: &String) -> &String {   // error: missing lifetime specifier
    if x.len() > y.len() { x } else { y }
}

Both borrows look completely reasonable on their own. But the strict friend stops you anyway, and this time it isn't because you broke the sharing rule from last chapter. It's a different worry: Sam's truck and Ann's truck aren't guaranteed to stick around for the same amount of time. Sam might toss his in a bin two seconds from now. Ann might hang onto hers all afternoon. Your function hands back one look — but a look at which truck? The strict friend has no way to know, just by reading your code, whether the look it's about to hand out is still safe once one of those two trucks is gone. So it refuses to guess, and it refuses to hand it out at all.

Put a matching tag on everything involved

Here's the fix, and it's smaller than it looks. You give the two trucks coming in, and the look going out, the same little tag — Rust's name for this tag is a "lifetime." You write it as a tick mark and a short name, usually just 'a, and you stamp it on every look in the signature:

rust — same tag on both sides, in and out

fn bigger_truck<'a>(x: &'a String, y: &'a String) -> &'a String {
    if x.len() > y.len() { x } else { y }
}

This is the part almost everyone gets wrong the first time, so say it slowly: writing 'a does not make anything stick around longer. It doesn't reserve a truck, and it doesn't ask Sam or Ann to wait. All it does is make a promise visible, so the strict friend can go check it: whatever look comes out of this function, trust it for no longer than the shorter-lived of the two trucks it might have come from. You're not setting a length of time. You're just telling the truth about a rule that was always going to be there anyway.

Try to use the result past the point where the shorter-lived truck is gone, and the strict friend still catches it — now it just knows exactly which line to point at:

rust — the tag makes the real danger visible

let sams_truck = String::from("big rig");
let bigger;
{
    let anns_truck = String::from("pickup");
    bigger = bigger_truck(&sams_truck, &anns_truck);
    println!("{}", bigger); // fine — ann's truck is still here
} // ann's truck is thrown away right here
// println!("{}", bigger); // error: ann's truck (and its tag) doesn't live that long

Most of the time, you never write the tag

Before you start bracing yourself to tag every look in every function you write from now on — don't. That two-truck function was a special, genuinely confusing case. Most of the time, the strict friend can work the tag out for itself, the same quiet way it works out most types without you spelling them out. It tries three habits, in order, before ever asking you for help:

The three habits the strict friend tries first

One: every look coming in gets its own private tag automatically. Two: if there's exactly one look coming in, the look going out is given that same tag, no questions asked. Three: if the function belongs to a thing (a look at itself), the look going out matches that thing's own tag. Only if all three habits still leave it stuck — like two trucks coming in and one look going out, with no way to tell which one it's from — does it stop guessing and ask you to write the tags yourself.

look_at, from last chapter, is a perfect example of habit two — one look in, one plain number out, no tag needed anywhere. Here's another: a helper that hands back a look at just the first word of a bigger sentence.

rust — one look in, one look out: no tag written, none needed

fn first_word(s: &str) -> &str {
    match s.find(' ') {
        Some(i) => &s[..i],
        None => s,
    }
}   // habit two: the one look coming in and the look going out share a tag

This is why explicit tags feel rare in real Rust code, even though every single look, everywhere, secretly has one. You only ever have to write 'a by hand once the strict friend runs out of safe guesses — usually, like bigger_truck, because more than one look came in and it truly can't tell which one the look going out belongs to.

A little card that remembers a look

Sometimes you don't want a look at a whole truck — just a look at one small part of it, written down on a little card you can carry around and hand to someone else later. Say you're reading a long storybook page and you want a card that remembers just its first line.

rust — a card that holds a look, not a copy

struct Highlight<'a> {
    line: &'a str,
}

fn main() {
    let page = String::from("Once upon a time.\nThe end.");
    let line_one = page.split('\n').next().unwrap();
    let note = Highlight { line: line_one };

    println!("{}", note.line); // fine — page is still here
}

The card itself needs a tag now, right there in <'a> on its own definition — because the card isn't holding the words themselves, only a look at where they live on the page. Once the card carries a tag, the strict friend can promise something useful: this card can never be used after the storybook page it points into has been thrown away. Try to keep the card around past the page's own room, and it's the same rejection as everything else in this chapter, just aimed at a card instead of a function's return value.

Some looks never expire

There's one tag that's special, and it's worth meeting by name because you'll see it in error messages sooner or later. Rust calls it "'static." A look tagged 'static is allowed to stick around for the entire time your program is running — no room, no closing door, ever.

You've actually been using it already. Any words you type straight into your code, in quotes, automatically get this tag:

rust — text written right into your code never expires

let greeting: &'static str = "I live for the whole program";

Here's the part that trips people up

When the strict friend gets confused about a tag, it will sometimes suggest slapping 'static onto the problem, as if that were a quick fix. Resist it. Almost always, the real issue is a look that genuinely doesn't live long enough, and forcing 'static onto it either doesn't fix anything or forces you to make the truck itself last the whole program — which is rarely what you actually wanted. 'static is a real, narrow promise, not an eraser for confusing messages.

Lifetime
A tag on a look that lets the strict friend check it can never outlive the thing it's a look at. It doesn't set or change how long anything actually sticks around.
Lifetime tag ('a)
The tick-and-letter you write when the strict friend can't work out which of several looks a returned look belongs to.
'static
The one tag meaning "good for the whole program, no room to outgrow." Every piece of text typed straight into your code carries it automatically.

Here's why it's worth putting up with. Lifetime messages are, honestly, some of the strangest-looking notes the strict friend ever hands you — full of ticks and letters that mean nothing the first time you see them. But underneath the odd spelling, they're catching something real: a look that might quietly point at a truck that's already gone, the kind of mistake that in most other languages doesn't announce itself until months later, in someone else's program, far from the line that actually caused it. Here, it's a note on your screen, today, before anything ever runs.

Because every borrowed look carries a tag the strict friend actually checks, you get to hand looks back out of deep, tangled code with total confidence — knowing it's simply not possible for one to point at a truck that's already gone.
