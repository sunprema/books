Plugins: Use Them Deliberately

Chapter seven's tmux-sensible mention was a preview, not the full story. tmux's plugin ecosystem covers real gaps — session persistence across a reboot, cross-platform clipboard integration, a status-line theme with real design behind it — that would take real effort to hand-roll. This chapter covers the manager that installs them, a short survey of the ones actually worth knowing by name, and the one discipline that matters more than any individual plugin: knowing what each line in your plugin list actually does before it's running on your machine.

The problem: real gaps, but unaudited code is the price

Chapter seven's tmux.conf and chapter eight's bindings are both entirely yours — every line is something you typed and (by the time you're this far into the book) understand. A plugin breaks that property on purpose: you're pulling in someone else's shell script and letting it run automatically, with your OS-level permissions, every time tmux starts or your config reloads. That's a real trade, not a free convenience — worth making consciously, plugin by plugin, rather than by copying a stranger's forty-line plugin list wholesale.

TPM: the plugin manager almost everyone uses

TPM (Tmux Plugin Manager) is itself a plugin, installed once by cloning it to a fixed path:

git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm

Plugins are then declared in tmux.conf with set -g @plugin '...' lines — a user/repo GitHub shorthand is enough — and the file must end with run '~/.tmux/plugins/tpm/tpm' as its literal last line, since that's what initializes TPM and sources everything declared above it:

# List of plugins
set -g @plugin 'tmux-plugins/tpm'
set -g @plugin 'tmux-plugins/tmux-sensible'
set -g @plugin 'tmux-plugins/tmux-resurrect'
set -g @plugin 'tmux-plugins/tmux-continuum'
set -g @plugin 'tmux-plugins/tmux-yank'

# Initialize TMUX plugin manager (keep this line at the very bottom of tmux.conf)
run '~/.tmux/plugins/tpm/tpm'

Three key bindings drive the whole lifecycle: prefix I (capital) fetches and sources any plugin newly added to the list; prefix U updates every installed plugin to its latest tracked commit; prefix alt-u (lowercase u) removes anything no longer present in the list. Reload the config after editing the plugin list, the same as any other config change — then prefix I to actually fetch what's new.

A short, deliberate list

Five plugins cover most of what's genuinely worth automating, each doing one specific thing:

PluginWhat it actually does
tmux-sensible a baseline of options its authors judge acceptable to everyone (near-zero escape-time, a larger history-limit) — chapter seven's config already set most of these by hand
tmux-resurrect save/restore session, window, and pane layout across a full reboot — the full treatment is next chapter
tmux-continuum automatic periodic saving on top of resurrect, and optional auto-restore on tmux start
tmux-yank copies tmux selections to the real OS clipboard across Linux/macOS/WSL, instead of only tmux's internal paste buffer (chapter five)
catppuccin/tmux the status-line theme from chapter nine, as composable pre-built segments

That's a complete, useful tmux setup in five lines, each doing something a hand-rolled equivalent would take real effort to match — cross-platform clipboard detection especially is not a weekend project. It's also short enough to actually remember what every line does, which is the entire point.

One plugin, installed manually

catppuccin/tmux's own README recommends installing it by hand — cloning it directly and adding a run-shell line yourself — rather than through TPM, because TPM has had plugin-name collisions with it in the past:

git clone https://github.com/catppuccin/tmux ~/clone/path
# then in tmux.conf:
run-shell ~/clone/path/catppuccin.tmux

Worth checking a plugin's own README for install instructions before assuming TPM is always the right path — most are, this one specifically says otherwise.

What "run with your permissions" actually means

Every TPM-managed plugin ships as an executable shell script — a *.tmux file, like resurrect.tmux or yank.tmux — that TPM sources with chapter thirteen's run-shell. There's no sandbox and no permission model beyond your own user account's: a plugin can read your files, make network calls, or modify your other dotfiles exactly as freely as a line you typed into tmux.conf yourself. That's not a tmux-specific flaw — it's how every plugin ecosystem built on "clone a script and source it" works — but it's the concrete reason "deliberately" belongs in this chapter's title.

A realistic workflow

Before adding a plugin: open its README, specifically its install and configuration sections, and confirm it actually does what its name implies before typing the @plugin line. Before pressing prefix U on an existing list: know that it moves every plugin to whatever its default branch currently points at — pinning a specific tag or commit (user/repo#v2.1.0 instead of bare user/repo) is worth doing for anything you'd be unhappy to see change silently underneath you.

Try it
  1. Install TPM if you haven't already, and add just tmux-sensible and tmux-yank to tmux.conf. Reload, then prefix I to fetch them.
  2. Confirm tmux-yank works: select text in copy mode (chapter five) with y and paste it into something outside tmux entirely, like a text editor or browser address bar.
  3. Run tmux show-options -g | grep escape-time before and after adding tmux-sensible, and notice which of chapter seven's hand-set options it would have set for you if you hadn't already.
  4. Open ~/.tmux/plugins/tmux-yank/yank.tmux in an editor and skim it — confirm for yourself it's a plain shell script, not some opaque binary, and that its actions match what its README claims.
Common mistake

Putting the tpm run line anywhere but the very last line. TPM has to be sourced after every @plugin declaration exists for it to know what to install, so a run '~/.tmux/plugins/tpm/tpm' placed in the middle of the file — easy to do by accident when adding a new section above an old one — means plugins declared below it silently never load. If prefix I doesn't seem to find a plugin you just added, check that line's position in the file before suspecting the plugin itself.

One plugin from the table above deserves more than a one-line summary: tmux-resurrect, and the automatic layer tmux-continuum builds on top of it, are the actual answer to a full reboot wiping out everything tmux was holding. That's next.
