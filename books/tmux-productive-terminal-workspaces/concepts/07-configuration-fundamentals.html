Configuration Fundamentals

Three separate promises have been quietly stacking up since chapter three: windows and panes start counting from 0, “unless you change that later in configuration”; mouse support has a mouse equivalent for “every binding above” once set -g mouse on is in your config, “covered properly in the configuration chapter”; scrollback defaults to 2000 lines, raisable with an option that only new panes see. This chapter is where all three get collected on, plus the handful of other settings worth having from day one — and, more importantly, where you learn what a tmux.conf actually is, so the next fifteen chapters of options stop feeling like magic incantations.

The problem: typing the same options every session

Every option you've seen so far — monitor-silence, remain-on-exit, set-clipboard — was set from the tmux command prompt or a shell command, live, inside a session that already existed. That's fine for something you're reaching for once, on the one window that needs it right now. It's not fine for “I always want the mouse on” or “I always want more scrollback” — typed at a prompt, either of those lasts exactly as long as the tmux server keeps running, and evaporates the next time you start fresh. What's missing isn't a new command; it's a place for the commands you want true by default to live, read automatically, before you've typed anything at all.

The idea: a config file is just commands, read once

A tmux.conf holds nothing you haven't already typed. It's a plain list of the exact same commands available at prefix : or as tmux <command> from the shell, one per line, read top to bottom. There's no separate configuration language to learn — if you know set -g history-limit 50000 works at a prompt, you already know how to write it into a file.

tmux looks for that file automatically the moment a new server starts: an explicit -f <path> on the command line wins outright; otherwise it reads ~/.tmux.conf if that exists; failing that, it falls back to $XDG_CONFIG_HOME/tmux/tmux.conf (or ~/.config/tmux/tmux.conf, if XDG_CONFIG_HOME isn't set). A system-wide /etc/tmux.conf, if your machine has one, is read first — before your own file — so anything you write afterward can still override it. For this book, one file is enough: ~/.tmux.conf.

The word “automatically” only covers new servers, though. Editing the file does nothing to a session already running — the same way editing a shell script doesn't change a copy of it already executing. To pull changes into a live server, reload the file explicitly: tmux source-file ~/.tmux.conf. Most of what this chapter covers takes effect the instant that command runs; a small number of once-only startup values genuinely do need a fresh server. Reloading is common enough to be worth a binding of its own, which is the first line in the starter config below — after that, editing and reloading is one keystroke, prefix r, instead of retyping the full command each time.

# pull an edited ~/.tmux.conf into the already-running server
tmux source-file ~/.tmux.conf

# or, once the binding from the starter config below is loaded:
# prefix r

Scope: server, session, and window options

Chapter six's key idea was that setw monitor-silence 30 — no -g — applies only to whatever window you're attached to, on purpose, so one build's monitoring doesn't bleed into every other window in the session. That was one instance of a rule worth stating in full now, because every option in this chapter (and most of the ones still ahead) is placed by it. Options live in a few separate namespaces: server options — rare, one setting shared by the whole tmux process and every client attached to it, changed with set-option -s; session options — changed with set-option, or its short form set; and window options — changed with set-window-option, or its short form setw. Within session and window options, -g is a second, independent axis: it decides breadth, not kind. -g sets the global default that every session (or window) inherits unless it has its own local override; leave it off and the command applies only to the current session, or, for setw, the one window you're currently attached to.

Command Namespace With -g Without -g
set-option -s server (whole process) no distinction — there's only one server
set-option / set session default for every session without a local override this session only
set-window-option / setw window default for every window without a local override this window only (chapter 6's monitor-silence)
Why almost everything below uses -g

While tmux is still parsing a config file at server startup, there is no session yet for a bare, non--g session option to belong to — some commands used that way can fail outright with an error like no current session. That's the practical reason a starting tmux.conf reaches for -g on nearly every line: a bare set/setw is a tool for the command prompt, changing something for just the session or window you're already attached to, not for a file read before any session exists.

Collecting on three promises

With scope out of the way, the options themselves are almost anticlimactic — each one is exactly the line chapters three, four, and five told you to expect, plus the default it's replacing.

Option Scope Default Starter value
mouse session off set -g mouse on
history-limit window (fixed per pane at creation) 2000 lines set -g history-limit 50000
base-index session 0 set -g base-index 1
pane-base-index window 0 setw -g pane-base-index 1

set -g mouse on is a single option (tmux 2.1 and later) standing in for what used to be several separately configured settings. On, it's the whole picture chapter four promised: click a pane to focus it, drag a border to resize, click a window's name in the status line to switch to it, drag inside a pane to select text into copy mode, and — the piece chapter five's copy-mode chapter assumed — scroll the wheel inside a pane to enter copy mode and scroll its history automatically. The trade chapter four already flagged still applies: your terminal emulator's own native click-drag selection steps aside once tmux owns the mouse, reachable again only with a modifier key held while dragging (which key depends on the terminal).

history-limit is exactly the option chapter five named: 2000 lines per pane by default, and raising it — set -g history-limit 50000 is a generous, common starting point — only reaches panes created after the change. Nothing about that changes here; this is just where the line that sets it permanently, instead of once from a prompt, actually goes.

base-index and pane-base-index are the “unless you change that later in configuration” chapter three warned about. Both default to 0, which means the first window you ever create is numbered 0 — sitting on the 0 key, at the far end of the row your other hand rests on, one key away from every other digit. Set both to 1 and the first window becomes window 1, directly under the 1 key that select-window -t N (chapter 3's prefix 0–9 bindings) already uses to jump straight to it. It's a small renumbering with an outsized effect on how much the keyboard row actually matches what's on screen. Like history-limit, it only takes hold for windows and panes created after the setting is in force — a session already running keeps its existing numbers until it's restarted.

A few more sensible defaults

Three options round out a config worth starting from, none of them promised earlier but each fixing something you'd eventually notice and go looking for. escape-time is a server option — the one line in this chapter that isn't session- or window-scoped — defaulting to 500 milliseconds: how long tmux waits after an Escape byte arrives to see whether more bytes immediately follow it, since arrow keys and other special keys are sent as escape sequences too. That wait is exactly the pause you feel leaving insert mode in Vim or Neovim inside a tmux pane. set -s escape-time 10 keeps it high enough to still recognize real escape sequences while removing the perceptible lag. renumber-windows, off by default, closes gaps left by a closed window automatically — without it, closing window 2 out of 0 1 2 3 leaves 0 1 3 until something is moved to fill the hole. And focus-events, also off by default, forwards terminal focus-in/focus-out events through to whatever's running in the active pane; Vim and Neovim use it so :set autoread actually reloads a file the instant focus returns to that pane, rather than only on the next keystroke.

Two status-line options are worth setting explicitly even at their defaults, mostly so they stop being invisible: status-position (bottom by default; top is the other option) and status-interval, which controls in seconds how often polled segments like the clock refresh — 15 by default, lower if you want it livelier. What actually goes inside the status line — content, color, segments — is deliberately not here; that's the next chapter but one.

The starter tmux.conf

Put together, every option above fits in about a dozen lines. This is a reasonable file to start from — not a plugin, not a framework, just the commands you've now read the reasoning for, grouped the way the scope model above groups them.

# ~/.tmux.conf -- see "Configuration Fundamentals" for what each line means
# reload after editing: tmux source-file ~/.tmux.conf (or prefix r, once loaded)

# --- server option: one setting for the whole tmux process ---
set -s escape-time 10          # default 500ms -- the pause before Esc registers in Vim

# --- session options: -g sets the default every session inherits ---
set -g mouse on                 # click to focus a pane, drag to resize, drag to select text
set -g history-limit 50000      # default 2000 lines/pane; only new panes see this
set -g base-index 1             # windows start at 1, lined up with the 1-9,0 select-window keys
set -g renumber-windows on      # closing a middle window closes the gap instead of leaving one
set -g focus-events on          # let Vim/Neovim autoread a file the moment focus returns

set -g status-position bottom   # already the default -- written out so it isn't a mystery
set -g status-interval 5        # default 15s; refresh the status line a little more often

# --- window option: setw -g sets the default every window inherits ---
setw -g pane-base-index 1       # panes start at 1 too, matching base-index above

# worth having before chapter 8 covers key bindings properly:
bind r source-file ~/.tmux.conf \; display-message "tmux.conf reloaded"
Key idea

None of these values are tmux's own defaults — they're this book's starting opinion, chosen and explained one at a time above. That's the whole point of understanding scope and defaults before copying a config from somewhere else: a plugin like tmux-sensible codifies a similar baseline (near-zero escape-time, a much larger history-limit) as a convenience, not a rulebook — and knowing what each line above actually does is what lets you keep, change, or drop any one of them later without breaking the rest.

A realistic workflow

The loop, once the reload binding exists, is short enough to repeat as many times as it takes: open ~/.tmux.conf in one pane, change or add a line, switch to any tmux session and press prefix r, and switch back. No restart, no detach-and-reattach, no losing the session you were testing the change in. That loop is also the fastest way to learn what's session-scoped versus window-scoped in practice: set an option with -g, reload, and check whether a different window or session picked it up too. If it didn't, the flag you needed was missing, and now you know exactly which line to fix.

Try it
  1. Create ~/.tmux.conf if you don't have one, and paste in the starter config above.
  2. From inside any tmux session, reload it by hand once (the binding isn't loaded yet): tmux source-file ~/.tmux.conf.
  3. Start a brand-new session — tmux new -s cfgtest — and confirm the first window is numbered 1, not 0, in the status line.
  4. Split it (prefix %) and confirm the mouse now resizes the border by drag and focuses a pane by click.
  5. Edit the file again: change status-interval 5 to status-interval 1. Switch to cfgtest and press prefix r — the bound reload, this time — and watch the status line's refresh rate visibly speed up with no restart.
  6. Finally, in that same session, run set history-limit 200 with no -g. Open a second session and check its history-limit (tmux show -g history-limit) — confirm it's untouched at 50000, since the command you just ran was scoped to cfgtest alone.
Common mistake

Editing tmux.conf, seeing no change, and assuming the option is wrong. Far more often, the file just hasn't been reloaded — a running server keeps whatever was true when it started (or when it was last reloaded) until source-file runs again, no matter how correct the new line is. Before doubting an option, doubt the reload: run tmux source-file ~/.tmux.conf (or prefix r, once bound) and check again. And if the option genuinely doesn't take effect even after a reload, check whether it's one of the rare once-only startup values that need a full new server, not a config re-read.

What's still using tmux's stock defaults is the single most-used mechanism in the whole program: the prefix key itself, Ctrl-b, along with every binding built on top of it. Changing those deliberately — remapping the prefix, adding bindings of your own, understanding command mode well enough to know what's safe to remap and what isn't — is a big enough topic to earn its own chapter next.
